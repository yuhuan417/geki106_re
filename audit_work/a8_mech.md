## 1. §15-1 结算面板统计字段（0x4CD4A0+0x18/+0x1C/+0x20）

### 证据

**字段性质**：+0x18/+0x1C/+0x20 与 +0x8/+0xC/+0x10/+0x14 是成绩对象的三对/一对累计量。

- 清零点 1（新局初始化 `0x45EB40`）：`0x45EB63 lea eax,[ebp+0x14]` +
  `0x45EB6C/6E/71/74 mov [eax]/[eax+4]/[eax+8]/[eax+0xC], edx(0)` ⇒ +0x14/+0x18/+0x1C/+0x20 = 0。
  调用点：`0x458DC9`（fn 0x458D60）、`0x45F5CC`（fn 0x45F5C0）。
- 清零点 2（关开始 `0x45EF10`，ecx=0x4CD4A0，`0x45EF10 lea edx,[ecx+0x14]` +
  `0x45EF15/17/1A/1D mov [edx..+0xC], eax(0)`）：+0x14/+0x18/+0x1C/+0x20 = 0；
  `0x45EF25 mov word[ecx+0x24], ax`（关卡）；`0x45EF2C mov edx,[eax*4+0x4A4B64]`、
  `0x45EF33 mov [ecx+0xEC], edx`（按关卡装载计分表指针，0x4A4B64[1..7] = 0x4993CC/38/80/B0/14/5C/C0）。
  调用点：`0x4545C4`（页13 enter 0x454280）、`0x45F5D4`、`0x460677`。
- **唯一累加写点 = `0x45E670`（this=ecx）**。全 exe `[ecx+0x18/+0x1C/+0x20]` 写点共 383 处，
  其中经 ecx=0x4CD4A0 可达的只有 0x45E670（另一处 0x4147E2 的 ecx=[ebx+0x38] 属别的对象）。
  签名（4 个栈参，`ret 0x10`）：`(this=ecx, a1=描述字指针, a2=门A, a3=门B, a4=门C)`：
  - `0x45E670 mov al,[esp+8]`（=a2 字节，门 A）；`0x45E69F cmp byte[esp+0x14],0`（=a3，门 B）；
    `0x45E6C5 cmp byte[esp+0x18],0`（=a4，门 C）。
  - 描述字 = a1：值 `[a1]`、屏蔽 `[a1+4]`（bit0=跳过 +0x20/+0x18/+0x1C，bit1=跳过 +0x10/+8/+0xC），
    `0x45E680/8F/6A6/B5/6CC/6DB test byte[eax+4],1/2`。
  - 门 A 开 → `0x45E687..0x45E68C [ecx+0x20]+=值`、`0x45E697..0x45E69C [ecx+0x10]+=值`；
    门 B 开 → `0x45E6AD..0x45E6B2 [ecx+0x18]+=值`、`0x45E6BD..0x45E6C2 [ecx+8]+=值`；
    门 C 开 → `0x45E6D1..0x45E6D8 [ecx+0x1C]+=值`、`0x45E6E1..0x45E6E8 [ecx+0xC]+=值`。
- 描述字来源 `0x45DFB0(dest, packed)`：`0x45DFBA 值=(packed&0x1F)×10^((packed>>5)&7)`、
  `0x45DFE1 mask=(packed>>8)&0xF`、`0x45DFEF n5=(packed>>0xC)&0xF`、`0x45DFF2 w6=packed>>16`。

**0x45E670 的全部 6 个调用点**（E8 扫 thunk 0x401451；this 一律 `mov ecx,ebp`=0x4CD4A0）：

| 调用点 | 所属 | 触发 | 实参 (a2,a3,a4) | 生效块 |
|---|---|---|---|---|
| `0x45EFBA` | `0x45EF50` ← `0x43BE6C`（0x43BDC0 列表插入尾部） | **每个实体入队**（arg=[入队记录+8]=type） | (1,0,0) | A：!(mask&4) 时 +0x20/+0x10 |
| `0x45F074` | `0x45EFF0` 头部（击杀必经） | 每次击杀计分 | (0,1,0) | **B：+0x18/+8**（除非 mask&1/&2） |
| `0x45F08D` | `0x45EFF0` | 击杀且击杀者表项 mask&4（`0x45F079 test [esp+0x14],4`） | (1,0,0) | A |
| `0x45F0E3` | `0x45EFF0` sel=0x300 | 僚机武器弹击杀 | (0,0,1) | **C：+0x1C/+0xC** |
| `0x45F143` | `0x45EFF0` sel=0x500 | 狙击击杀 | (0,0,1) | C |
| `0x45F229` | `0x45EFF0` sel=0x400 | 捕获击杀 | (0,0,1) | C |

（0x45EFF0 的 this=0x4CD4A0 由 4 个击杀回调调用点的 `mov ecx,0x4CD4A0` 证实：
0x43C2D7/0x43C60D/0x43CAB4/0x43D36E；0x45EF50 的 this=0x4CD4A0 由 0x43BE67 证实。）

**读取点**：
- `0x45F9D0`：`mov eax,[ecx+0x20]; mov edx,[ecx+0x18]; push eax; push edx; call 0x40233D(→0x45E7A0)`
  ⇒ **千分比 = +0x18×1000 ÷ +0x20**（击杀价值/出现价值，0x45E7A0: `0x45E7A4 test ecx,ecx` b=0→0，
  `0x45E7C4..0x45E7D2` a×1000/b）。调用点：`0x423065`（结算面板建立 0x423027）、
  `0x45E9CA`（0x45E7F0 result 文本聚合）、`0x45F713`（0x45F710 分数换算，面板收尾 `0x423A8E` 调用）。
- `0x45FA00`：`mov eax,[ecx+0x18]; mov edx,[ecx+0x1C]; push eax; push edx` ⇒ **千分比 = +0x1C×1000 ÷ +0x18**
  （特殊武器击杀价值/总击杀价值）。调用点：`0x423072`、`0x45E9F3`、`0x45F72B`。
  两处面板读取都带 `mov ecx,0x4CD4A0`（0x423060/0x42306A）。
- 面板 `0x423A40`（thunk 0x4019EC，实体 `0x51000001`）：`0x423A45 [esi+0x30]` 门开时每帧
  `0x423A5A/0x423A70 显示值 += 0xC8(200)` 且目标递减，归零后 `0x423A89 mov ecx,0x4CD4A0; call 0x401BB3(→0x45F710)`
  收尾并 `xor al,al` 自灭；`0x4AB596` 非零才检查归零（`0x423A75 cmp byte[0x4AB596],cl`）。

### 结论

**§15-1 原 premise（“计数恒 0、面板数字为 0、0x423A40 首帧自灭是忠实”）不成立。**
+0x18/+0x1C/+0x20 在正常游戏流程中持续增长：

- **+0x18（+0x8）**：每次击杀计分（0x45EFF0 头部无条件块 B，0x45F074）都累加击杀者表项价值
  （除非表项 mask&1）。三对里它是比率分子。
- **+0x1C（+0xC）**：sel=0x300（僚机武器弹 0x11FFA321/24）/0x400（捕获 0x10008431）/0x500
  （狙击 0x41400507）击杀时累加（0x45F0E3/0x45F143/0x45F229）。即“特殊武器击杀价值”。
- **+0x20（+0x10）**：主体来自**每次实体入队**（0x43BDC0 尾部对入队 type 查表，mask&4==0 时累加，
  0x45EFBA）——即“出现价值”的分母；另加 mask&4 类型击杀（0x45F08D）。
  表项 mask 分布（0x4A4B64 各关表实测）：mask=0 约占 80–90%，mask&4 约 7%，mask&1 约 10%。

因此原作结算面板（0x423027 建立、0x423A40 步进）显示的是**真实千分比率并滚动 200/帧动画**，
收尾时 `0x45F710` 把两个比率 ×200 加回分数并调 `0x45E7F0` 生成 result 文本。
“计数恒 0”的旧结论来自只扫了 `inc/add [disp]` 而漏掉 this-call 别名写（`mov [ecx+off]`）。

### 对复刻代码的影响

- `remake/pygame/page4.py` 的 `p4_45eff0`/`p4_45e670` 已按 (rec, 门A, 门B, 门C) 正确实现击杀侧
  累加（+0x18、+0x1C、mask&4 的 +0x20）。
- **缺口**：0x45EF50 的入队侧累加未落地（`p4_hud_get` 无调用方且注释“写回尚未解故不执行”；
  其 `p4_hud_accum` 的门位映射也与 exe 不符——exe 门是 (a2,a3,a4) 字节，不是 value 低位）。
  需要在每个 `0x43BDC0` 等价入队点补：查 type&0xFF 表项 → mask&4==0 时按 mask&1/&2 累加
  +0x20/+0x10。否则复刻的 +0x20（分母）只含 mask&4 击杀，比率会 >1000‰。
- 结算面板（`_beh_423A40`）逻辑本身正确，计数补齐后即自然显示真实比率。
- 另注：`p4_hud_accum`（line 2233）与 `p4_45e670`（line 19764）是两份重复实现，建议合并到后者。

## 2. §15-4 0x45EFF0 sel 分支触发条件与频率

### 证据

- 签名：`0x45EFF0(this=0x4CD4A0, a1=靶类型, a2=击杀者类型, a3=x, a4=y)`
  （`0x45F00C mov ebp,ecx`；`0x45F01C mov eax,[esp+0xE8]`=a1（查表）；
  `0x45F092 mov eax,[esp+0xF8]`=a2；`0x45F0F6/0x45F0FF [esp+0xFC]/[esp+0x100]`=a3/a4）。
  头部 `0x45F00E mov ecx,[ebp+0xEC]; test ecx,ecx; je 0x45F3FA`（表未装载直接返回）。
  **sel = a2 & 0xF00**（`0x45F099 and eax,0xF00`），即击杀者 type 第 2 字节低 nibble ×0x100。
- **全部调用点 = 4 处**（0x45EFF0 仅被 thunk `0x401F96` 引用；E8 扫描 + 全镜像 dword 扫描均无其它引用）：

| 调用点 | 函数（身份） | a2（击杀者） | sel |
|---|---|---|---|
| `0x43C2E2` | `0x43C170`（碰撞组1 演员×敌机命中回调，0x43BFD0 于 0x451480 每帧调用） | 常量 `push 0x100D1211`（0x43C2D1）＝捕获僚机通常攻撃弾 | **0x200** |
| `0x43C61D` | `0x43C460`（组2 命中主到的捕获成功支） | 常量 `push 0x10008431`（0x43C607）＝捕获束 | **0x400** |
| `0x43CAB9` | `0x43C460` 伤害路径（0x43C9C2 分支） | 动态 `mov eax,[ebx+0x14]`（0x43CAAA）＝命中弹 type | 弹型 nibble |
| `0x43D373` | `0x43D250`（狙击命中结算，beh 0x429F20 于 0x42A11D 调用） | 动态 `[ebx+0x14]`，`0x43D26B cmp eax,0x41400507` 显式判狙击驱动器 | **0x500** |

- 各 sel 分支体（0x45EFF0 内，均为每击杀一次，无额外频率门）：
  - `0x45F0C9`（0x100）：`ebx=[esp+0x10]`（表价值）；`0x45F0CD inc word[ebp+0x26]`（计量器+1）。
  - `0x45F0B9`（0x200）：`ebx=价值×2`；计量器+1。
  - `0x45F0D6`（0x300）：`0x45E670(rec,0,0,1)`（+0x1C/+0xC）；`0x45F0F1 call 0x401721(→0x45E710)`
    倍率 = `(min(d,100)+min(word[+0x2C],10))×n5×价值`（d=8）；`0x45F10B 0x45E4A0` 出得分汉字。
  - `0x45F212`（0x400）：`inc word[+0x58]`；`0x45F223 mov word[+0x26],0`（计量器清零）；
    `0x45E670(rec,0,0,1)`；倍率 d=2。
  - `0x45F12B`（0x500）：`inc [ebp+0x54]`；计量器+1；`0x45E670(rec,0,0,1)`；倍率 d=word[0x56CCA4]；
    `0x45F175 inc word[+0x28]`，≥0x32（50）→ 造 0x32000004 入 0x4AD49C 并清零；
    `0x45F1CC byte[+0x2A]` 非零 → `inc word[0x56CCB0]` + 造 0x32000005（赏字链）。
  - 其它（含 sel 0）：`0x45F240 ebx=[esp+0x10]`（只加分，无计数无字形）。
- 玩家弹型 → sel 实测：0x120B1121/0x12091122/0x12061124/0x12041129→0x100；
  0x100D1211/0x10032215→0x200；0x11FFA321/0x11FFA324→0x300；
  0x1180A322/0x1140A323/0x1140A325/0x11C0A326/0x10008041/0x10FF0053→0x000；
  0x41400507（狙击驱动器，0x41族）→0x500。

### 结论

**可闭合，无需实机对照。** 0x45EFF0 每次击杀事件恰好执行一次，分支由击杀者 type 完全决定：
1. 碰撞组 1（演员×敌机）击杀 → 恒 sel 0x200（击杀者常量 0x100D1211）；
2. 捕获束命中转化 → 恒 sel 0x400（击杀者常量 0x10008431）——频率受计量器
   `word[0x4CD4A0+0x26] ≥ 0xA0`（0x45FAB0 setge）与束冷却 `[player+0x28]` 限制；
3. 组 2 伤害击杀 → sel = 弹型 nibble（0x100 普通弹族 / 0x300 僚机武器弹 / 其余 0）；
4. 狙击驱动器命中击杀 → 恒 sel 0x500（0x41400507）。
连击/波纹/赏字链的“频率”就是对应武器击杀频率本身：每击杀计数器 +1（0x100/0x200/0x500）或
按 50 次狙击击杀出 0x32000004、byte[+0x2A] 触发 0x32000005，全部确定性、无 RNG。

### 对复刻代码的影响

`p4_45eff0` 的 sel 分发与分支体已与 exe 一致（含 `sel=arg2` 的校正注释）。
剩余缺口：捕获击杀点（0x43C61D，`page4.py` line 21027 标“未落地”）与狙击/组 2 伤害路径的
`p4_45eff0` 实际接线需按本表 sel 传入（0x43CAB9 用命中弹 type，0x43D373 用 0x41400507）。

## 3. §15-5 “键位绑定 blob” 0x445062 的落盘路径

### 证据

- 0x445062 位于页脚本/记录处理函数 `0x444F7A` 内。`0x445059 cmp edi,0x10; jne 0x4453D2`、
  `0x445062 push 0x80; mov ecx,0x4AB5B0; call 0x40208B`（旗标 bit0x80 门）。
- 随后 `0x445079..0x445395` 把 `0x4A4080..0x4A40F7` 的内容按 7 字节组
  （dword+word+byte）拷入栈缓冲，每组补 0x39 字节 0（`mov ecx,0xE; rep stosd; stosb`，
  如 0x4450A3/0x4450BA/0x4450BC）——即把 7 字节数据变成 0x40 字节 **NUL 结尾字符串**。
- 缓冲消费：`0x445395 call 0x4022C0` → **`0x44D330`（GDI TextOut 文字路径）**；
  备用支 `0x445409 jmp 0x445386` 同汇合；无任何 CreateFile/WriteFile 链。
- **0x4A4080..0x4A40F7 的实际内容**（.data 初始化数据，全 exe 无写点——直接 disp 引用全是读）：

```
"NameEntry\0\0\0Ending\0\0LastBoss\0\0\0\0Boss2\0\0\0Boss1\0\0\0Stage7\0\0Stage6\0\0
Stage5\0\0Stage4\0\0Stage3\0\0Stage2\0\0Stage1\0\0PlayerSelect\0\0\0\0"
```

  即 13 条 7 字节布景名串（PlayerSelect/Stage1..7/Boss1/Boss2/LastBoss/Ending/NameEntry），
  是**記録/选关页的行名静态文本**，与键位绑定无关。

### 结论

**§15-5 的 premise 误判。** 0x445062 不是“键位数据序列化”，而是把 .data 里的 13 条静态布景名
字符串展开成 0x40 字节文本缓冲交给 GDI TextOut（0x44D330）绘制——纯显示路径，
**不存在对应 blob 的落盘**（无文件名引用、无 CreateFile/WriteFile）。键位持久化仍只有
GRCD（state.dat）的 `keys.bits/disp_cfg.bits` 与排行表，复刻侧“会话内镜像”无需再追落盘。

### 对复刻代码的影响

无。可在 §15 删除该项；若要注释 0x445062，应标注为“記録页布景名文本展开（0x44D330 绘制）”。
（顺带：`docs/p4_replay_save.md` line 110 所记“0x426EB0/0x449E10/页12 0x4537F1/页5 0x43DD20 把
项+0x4C 交给 0x45FE10”与此一致——它们是排行记录的场景重建，不是键位。）

## 4a. §15-2 0x23000006 的 rec 0x40E528 “未初始化栈缓冲”

### 证据

- `0x40E520` 是 `0x23000005`/`0x23000006` 共用行为（thunk 0x401BD1；ctor 跳表
  `0x40DE98` 索引 = type−0x23000001：case5→0x40DA40 两型 beh 同为 0x401BD1）。
  `0x40E528 mov eax,[ebp+0x2C]`（子体数 N）非 0 时进入生成块：
  - `0x40E535 lea eax,[esp+0xC]`、`0x40E539 push eax`、`0x40E53A push 0x23000006`、
    `0x40E53F push [ebp+8]`、`0x40E544 push [ebp+4]`、`0x40E545 push &[esp+0x18]`、
    `0x40E546 call 0x4023C4(→0x430400)`。
  - `0x430400`（逐字节核过：`83EC14…F3A5…C3`）只是 5 dword 复制器：payload =
    {a2=[ebp+4](x), a3=[ebp+8](y), a4=0x23000006(type), a5=&[esp+0xC](参数指针 p[3]), 第5槽}。
  - `0x40E55B add esp,0x14` 后 `0x40E563/0x40E567/0x40E56D rep movsd` 把 payload 复制到 [esp+0x28]；
  - **`0x40E56F mov [esp+0xC], ebp`**（p[3][0] = 父实体指针）；
  - 循环 `0x40E575..0x40E597`：`0x40E578 lea edx,[esp+0x28]`、
    **`0x40E581 mov [esp+0x10], ecx`（p[3][4] = −8×当前计数）**、
    `0x40E585 push edx; 0x40E586 mov ecx,0x4AD43C; 0x40E58B call 0x401FA5(→0x43BDC0)` 入队。
- 子体 0x23000006 的 ctor 分支 `0x40DA40`（经 0x43BDC0→malloc 0x5C→0x43A7F0→0x40D940）：
  `0x40DA4E mov ecx,[eax+0xC]`（p[3] 指针）、`0x40DA51 mov edx,[ecx]`（**解引用**）、
  `0x40DA53 mov [esi+0x1C], edx`（= 父指针）；`0x40DA56/0x40DA59/0x40DA5C mov ecx,[eax+0xC]`、
  `mov ecx,[ecx+4]`、`mov [esi+0x20], ecx`（= 相位 −8×i）；`0x40DA5C/62/65` 清 +0x24/+0x28/+0x2C。

### 结论

**不是 UB。** “未初始化栈缓冲”只在 `0x40E535 lea` 那一刻成立；真正消费它的是入队时的
子体 ctor（0x40DA40），而那一刻之前 `0x40E56F` 已写 p[3][0]=父指针、`0x40E581` 已写
p[3][4]=−8×剩余计数，且每轮循环先写后插。子体实体 +0x1C=父指针、+0x20=−8N..−8 相位种子，
完全确定——正是 ANALYSIS §7 记载的“子持父指针与 −8N..−8 相位”。

## 4b. §15-3 0x4100000D 的 4 处引用可达性

### 证据

ctor `0x4293F8`：`0x4293FF mov [esi+0x1C],-1`、beh=`0x4022F7`；`0x429406 mov eax,[esp+0x18C]`
