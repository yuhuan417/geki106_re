# 回放/存档持久化：GRPD／GRCD 全链定案（2026-11-12，闭合 ANALYSIS §15.4）

> 全部结论出自 `geki106.exe` 反汇编（字节级复核）。LZ 格式与 `grod_decode.py`
> （已通过 resource.rom 校验和验证）同源——存档/回放的负载压缩与资源包共用同一编解码器。

---

## 1. LZ 编解码器（GROD 格式）

- **压缩 `0x45B340(data, size)`**（返回压缩后大小，**0 = 不可压缩**，此时调用者存原始字节）：
  - 输出原位覆写（`0x45B5DB` 把压缩结果拷回输入缓冲）；
  - `out[0]` = 校验和低字节（`Σ data[i]*i`，`0x45B37A..0x45B389`）、`out[1]` = 标记字节
    （频次最高的字节，`0x45B3F1..0x45B411`）；
  - token 流：字面量 = 原字节；标记后 `count` 字节：`count==0` → 字面量标记本身；
    否则 `dist = count>>3`（0..31，回看窗口 `max(0, i-0x1F)`，`0x45B491`）、
    `len = (count&7)*4 + 4`（4..32，dword 对齐匹配，`0x45B4C3..0x45B539`）。
  - 与 `grod_decode.py` 的 token 格式一致（该解码器已通过 resource.rom 校验和）。
- **解压 `0x45B6E0`**（thunk `0x401AD2`）：GROD 解码器本体（§5.1 已定案），
  在回放/存档路径以 `(dst, 长度)` 形式从会话读游标解码。

## 2. 文件缓存 / 会话类（0x455090 族）

- `0x455090(session, filename, index, flag)`：关闭旧句柄（`0x455350`）→ `[+8]=index` →
  预载重映射（`[0x4AA49C]` 且 index==0 且 flag==0 → index 0→4，配 `Now Loading`）→
  在 250 项名字表 `0x4AA0B4` 中查重 → `0x454FB0(filename, mode)` 打开
  （**mode 0="rb" / 1="wb" / 2="ab"，模式表 `0x499024`，路径 = 基址槽 `0x4A99CC+0x100*k`（8 槽）+ 文件名**）→
  ftell 取大小 → 名字/数据入预载表（`0x4AA0B4[idx]`=名字副本、`0x4A9CCC[idx]`=块，
  块首 dword = 大小）→ `fwrite` 写回。
- `0x455640(session, buf, size)`：`fwrite(buf, size, 1, [session+4])`。
- `0x455500(session, buf, size)`：读——index<250 从预载表 `[0x4A9CCC+idx*4]+[+0x10]` 游标读，
  否则 `fread`；`[+0x10]` = 读游标。
- CRT 包装：`0x4634AC`=fopen、`0x4637D6`=fseek、`0x463653`=ftell、
  `0x46353C`=fwrite、`0x46388F`=fread、`0x4634BF`=fclose。

## 3. GRPD 回放文件（rp_*.dat）

### 3.1 文件名 `0x45CFB0`（ret 0x14）

- slot==99(0x63) → **`rp_last.dat`**（页4 收尾自动保存）；
- 否则 `rp_gm_`（普通局，[mgr+0x20]==0）/ `rp_tr_`（鍛錬）＋ `j_`/`m_` ＋
  `sprintf("%s%02d_", …, slot)` ＋ `gek.dat`/`rin.dat`/`kan.dat`（按机体）。
  例：`rp_gm_j_00_gek.dat`、`rp_tr_m_03_rin.dat`。
- 读取时（`0x45D700`）对 j/m 两种拼法**重试 3 次**。

### 3.2 写入 `0x45D460(mgr, slot)`（ret 8；页4 收尾 `0x451CBF` slot=99、
页8/9/10 收尾 `0x4535E4`、页5 槽管理 `0x45C7D0` ×3）

1. 三次 `0x45CFB0` 生成文件名（j/m 变体试写）。
2. 缓冲对象（`0x45B120`，vtable `0x4993B8`）resize 为 `frames*3+1`
   （frames = `[mgr+0x9E37C]`）；把三个字节平面从 SoA 区
   （`[mgr+0x30]`/`[mgr+0x34BF0]`/`[mgr+0x697B0]`，步距 0x34BC0）
   各拷 `frames` 字节（+`frames&3` 尾巴）打包。
3. `0x45B340` 压缩 → `[mgr+0x10]`=压缩后大小、`[mgr+0xC]`=frames；
   `[mgr+0x22..0x2B]` = 压缩器头 10 字节（从压缩结果拷入）。
4. `0x455090` 登记/打开文件 → `0x455640` 写 **0x2C 字节头**（= `[mgr+4..0x2F]`）→
   `0x45B1A0` 收尾。

### 3.3 GRPD 头（0x2C 字节，= 回放管理器 `[+4..+0x2F]`）

| 偏移 | 内容 |
|---|---|
| +0x00 | `'GRPD'`（0x44505247） |
| +0x04 | 版本 `'106A'`（读取端另接受 `'105A'`/`'100B'`，且须经兼容表 `0x45A650`/链头 `0x49934C`） |
| +0x08 | frames（`[mgr+0xC]`） |
| +0x0C | 压缩后大小（`[mgr+0x10]`） |
| +0x10..+0x1F | 阶段参数块 dword（`0x45D160` 从参数块拷入的残余 4 项） |
| +0x22..+0x2B | 压缩器头 10 字节 |
| +0x2C | 阶段参数块末 dword |

（`0x45D160` 先把 11 dword 参数块拷到 `[+4..+0x2F]` 再覆写前两个 magic——
即参数块的前两 dword 被魔数替换，其余 9 dword 保留；随后 frames/compSize/压缩头覆盖对应槽。）

### 3.4 读取 `0x45D700(mgr, …)`（ret 0xC；页5 选单 `0x43E991` 调用）

文件名 3 试 → `0x455090` 打开 → 清零 SoA 区 → 读 0x2C 头 →
验 `'GRPD'` + 版本（106A/105A/100B + 兼容表）→ 按 `[mgr+0xC]` frames 分配
`frames*3+1` → 读压缩负载 → `0x45B6E0` 解压 → 三字节平面拆回 SoA → 返回 1。
头 11 dword 回灌由 `0x45D1A0`（`rep movsd 0xB` 从 `[mgr+4]` 到参数块）完成——
**页11 用它恢复阶段配置**（p4_enter §1.2）。

## 4. GRCD 系统存档（state.dat / netstate.dat）

### 4.1 写入 `0x45CB70(表对象)` —— **仅在程序退出时**（`0x458640` 关闭序列 `0x401F3C` 调用）

1. 遍历两 Bank 的槽（Bank1 10 槽自 `[this+0x738]` 向下步 0xA8、Bank2 11 槽自
   `[this+0xF18]` 向下步 0xA8），累加 `[[槽]+0] + 0x54`（记录 0x54 字节 + 附件大小）。
2. 分配总大小缓冲，`0x45B2D0` 逐记录拷入（0x54 记录 + 附件字节流）。
3. `0x45B340` 压缩两段 → 头 0x18 字节：`[+0]='GRCD'`、`[+4]='106A'`、
   `[+8]`=第一段原始大小、`[+0xC]`=第一段压缩大小、`[+0x10..0x17]` 头余量。
4. `0x455090` 打开 **`state.dat`**（0x4A4AF4；arg 非 0 时 `netstate.dat` 0x4A4AE4）→
   写 0x18 头 + 负载（0x455640 ×2）→ `0x45B1A0` 收尾。

### 4.2 读取 `0x45C020(flag)`（启动时 `0x45C5F0→0x45C610` 调用）

打开 state.dat / netstate.dat → 读 0x18 头 → 验 `'GRCD'` + 版本（0x45A650 兼容表）→
分配 `[+8]` → 读 `[+0xC]` 字节负载 → `0x45B6E0` 解压两段 →
逐记录 `0x4015D2→0x45B260` 读 0x54 字节 + `[rec]` 大小的附件（malloc 入 `[rec+0x4C]`）。

### 4.3 记录布局（0x54 字节 + 附件）

- `[+0x00]` = 附件大小（dword，写入/加载都以它计长）
- `[+0x28]` = 舞台选择器（页5 装载时 `0x43E9B0` 写回 `[0x4AB5C8]`）
- `[+0x20]`/`[+0x24]` = 驻留计数/段（p5_rank_notes）
- `[+0x4C]` = 附件指针（内存态；文件流中附件紧随 0x54 记录之后，前缀 u32 大小）
- 附件 = 该记录对应的**回放负载**（与 GRPD 的三字节平面同格式）

## 5. 帧编解码（0x18 字节输入记录 ↔ 23 位 packed）

**编码 `0x45CEA0(rec, mgr, idx)`** / **解码 `0x45CF20(mgr, idx, out)`**：

```
packed = (dx & 0x7FF) | ((dy & 0x3FF) << 11) | (btn0 & 1) << 21 | (btn1 & 1) << 22
```
- dx = rec[0..3]（11 位，解码时按 bit10 符号扩展）、dy = rec[4..7]（10 位，bit9 符号扩展）、
  btn0 = rec[8]&1、btn1 = rec[9]&1（0x18 字节帧输入记录 §10.2）。
- 三个字节平面写入/读出：`[mgr+0x30+idx]`（byte0）、`[mgr+0x34BF0+idx]`（byte1）、
  `[mgr+0x697B0+idx]`（byte2）——"三数组 SoA" 实为**字节平面拆分**；
  每平面容量 0x34BC0(216000) 帧，`[mgr+0x9E37C]`=帧计数、`[mgr+0x9E380]`=播放游标、
  `[mgr+0x9E378/9]`=前帧键态（边沿重建 `0x45D2B0`）。
- 归档笔记的"第 23 位时间标记"：由录制侧 `0x45D1D0` 的分段时间戳机制承载，
  不在 23 位 packed 内。

## 6. 回放管理器 `0x4CD5D8` 字段补全

| 偏移 | 含义 |
|---|---|
| +0x04..+0x2F | GRPD 头（0x2C，§3.3） |
| +0x10 / +0x0C | 压缩后大小 / frames（写时更新） |
| +0x22..+0x2B | 压缩器头 10 字节 |
| +0x30 / +0x34BF0 / +0x697B0 | 三个字节平面（每面 0x34BC0） |
| +0x9E370 / +0x9E374 | 播放相关计数 |
| +0x9E378 / +0x9E379 | 前帧 btn0/btn1（边沿重建） |
| +0x9E37C | 帧计数 |
| +0x9E380 | 播放游标（页4 调试文字读它） |

## 7. 实机文件验证（ground truth）

用 `../geki106/` 里的真实存档对本文布局做了完整往返验证（脚本化解码）：

**`rp_last.dat`（3743 字节）**：
- 头 0x2C：`'GRPD' '106A'`、frames=2618（+0x08）、compSize=3699（+0x0C）；
  文件 = 0x2C + 3699 = 3743 整，无尾随字节；
- 负载按本文 LZ 直接解码得 **7855 = frames*3+1** 字节，校验和通过；
- 三字节平面拆包 → 23 位帧解码：dx/dy 为**指针增量**（±几百，idle 时 0）、
  btn0 按住 1989 帧、btn1 1294 帧 —— 与输入记录语义一致。

**`state.dat`（97430 字节）**：
- 头 0x18：`'GRCD' '106A'`、`[+8]`=147384、`[+0xC]`=127316；负载 97406 字节；
- 负载为 **双重 LZ**：第一遍解出 127316 = `[+0xC]`，第二遍解出 147384 = `[+8]`
  （两个头字段 = 内/外层解压后大小），与 `0x45CB70` 的两次 `0x45B340` 调用对应；
- 外层数据流 = 0x54 记录 + 附件（首记录 `[rec+0]`=附件大小，步进自洽）。
  0x54 记录的完整字段表归 p5_rank_notes 验证。

**GRPD 头 +0x18/+0x19 实测 = 0x64(100)/6（普通局 继续门/命数）**——与
`p4_enter_0x4505B0.md` §2.0/旁路表的 +0x19/+0x1A 相差 1 字节（旁路 stores
`0x450665/0x450678` 的 esp 位移需按 B-4 拷贝基址重推）；p4_enter 相应表待订正，
以实机文件为准。
