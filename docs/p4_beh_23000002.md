# 页4 实体类型 `0x23000002`：行为逐条定案

> 依据：`../geki106/geki106.exe`（基址 `0x400000`）。工具：本仓库 `re_dis.py`
> （`R.dis()/R.dec()/R.insns/R.xrefs()`，递归下降反汇编 + 原始字节核对）。
> 记号：`ent` = 实体基址（`this`），`p` = ctor 的 payload 指针，`node` = `[ent+0x38]` 显示节点。
> 本文只定案 **`0x23000002` 这一个类型**；ctor 公共部分/`0x498000` 表 26 条见
> `docs/p4_ent23_fields.md`（其数值与本文 §2 完全一致），`0x40213F` 链见
> `docs/p4_beh_23000003.md`（本文 §8 补上它生成的**类型号**）。

## 0. 结论速览

**它是什么**：关 1 的 `bm_s1.ggd`（敌字形图集，528×288 = 11×6 个 48×48 格）里的
**第 1 格**（源左上 `(48,0)`）的一块 48×48 贴片。从 `x=664` 出现，向左 4 px/帧横移；
`t=20..59` 期间纵向按 `[ent+0x20]`（±1，由出生 y 决定）累积加减速，位移峰 **+105 / −95 px**
（`(v+2)>>2` 向下取整 ⇒ 上下方向不对称）；
`t=140..172` 横向减速到 0 再反向加速到 +4 px/帧，随后向右**穿出右边界**（`x>=680` 当帧自毁）。
`payload[0xC]==1` 的个体在 `x` **恰好等于 400** 的那两帧各往队列 `0x4AD49C` 生成一枚 **`0x31000001`**。

**每帧唯一的一次贴屏**（三元组，全部为常量或实体字段的线性式）：

| # | 时机 | 层 | 源矩形 (l,t,r,b) | 目标点 (屏幕) | 标志 | 依据 |
|---|---|---|---|---|---|---|
| 1 | 每帧行为返回 1 后（`0x458EF0` 渲染 pass） | **2** | `(0x30, 0, 0x5F, 0x2F)` = `(48,0,95,47)`，再经 `(0,0,640,480)` 裁剪 | `(x-0x18, y-0x18)` = `(x-24, y-24)` | `0x11`（SRCCOLORKEY，色键 0） | 层/矩形 `0x43ACC3/0x43AC95`；dst `0x40E1C1`；blit `0x45A264→0x44D010` |

- 层 2 在关 1 由 `OP0B` 装的是 **资源 id 32 = `bms1\bm_s1.ggd`**（`OP0B layers=[7,8,32,5,5,5,36,37,38,39,40,41,5,43]`，
  `0x46060F` 循环：层号 = 循环变量 `edi`，资源 = 表项，值 `5` 跳过）。
- 该实体**不调用** `0x44D060`，也不会给 `0x44D0B0/0x44D120/0x44DB80` 之类自带 blit 复核；
  贴屏一律走通用显示表渲染 `0x45A170` → `0x44D010`（§6）。

## 1. 入口链（脚本 → 实体 → 行为指针）

```
脚本 OP02 (x, y, type=0x23000002, param)
  └ 0x430400 打包 0x14 字节 payload：payload[0]=x, [4]=y, [8]=type, [0xC]=param   (0x43040F..0x430434, rep movsd 5)
      └ 0x43BDC0（= thunk 0x401FA5，队列 0x4AD43C 的入队原语）
          └ 0x47C7C0(0x5C) 分配实体 → ctor 0x43A7F0(payload)         (ANALYSIS §16.121)
              └ 0x40180C(=0x430450 公共头) → 0x49874C vtable
              └ type & 0x2F000000 == 0x23000000 → 0x4013D9
                  └ 0x4013D9: jmp 0x40D940（裸跳，ecx 由 0x43A88D 提供）
                      └ 0x40D940: 先 0x43AC30(ent, 0x498000) 查属性表（§2）
                                 再 case 分派 jmp [eax*4+0x40DE98]，eax = type-0x23000001
                          type 0x23000002 → eax=1 → **case 1 = 0x40D985**
```

关键写入 `[ent+0x40]`（行为指针）的正是 case 1 的第一条有效指令：

| 地址 | 指令 |
|---|---|
| `0x40D998` | `mov dword ptr [esi+0x40], 0x401FF0` |
| `0x401FF0` | `jmp 0x40E100`（thunk，无参数改写） |

调用点（每帧一次）：`0x43BC70`（队列 `0x4AD43C` 的 tick）→ `0x43BC88 call 0x40131B`
→ `0x43AD40: jmp dword ptr [ecx+0x40]`；返回值在 `al`（§7）。

## 2. ctor：case 1（`0x40D985`–`0x40D9C2`，`ret 4`）

payload 指针在 `[esp+0x3C]`（`ret 4` + 已压 4 个寄存器 + `sub esp,0x28`，见 `0x40D988`）。

| 地址 | 指令 | 效果 |
|---|---|---|
| `0x40D985` | `mov ebx,[esi+8]` | ebx = 出生 y |
| `0x40D988` | `mov eax,[esp+0x3C]` | eax = payload |
| `0x40D98C`–`0x40D9A5` | `xor edx,edx; cmp ebx,0xF0; setle dl; dec edx; and edx,2; dec edx` | `edx = (signed)y <= 0xF0 ? -1 : +1` |
| `0x40D998` | `mov [esi+0x40],0x401FF0` | **行为指针** |
| `0x40D99F` | `mov ecx,[eax+0xC]` | param = payload[0xC] |
| `0x40D9A6` | `xor ebx,ebx` | |
| `0x40D9A8` | `mov [esi+0x1C],ecx` | **`+0x1C` = param**（唯一用途：§8 的触发开关） |
| `0x40D9AB` | `mov [esi+0x20],edx` | **`+0x20` = ±1**（纵向加速度方向） |
| `0x40D9AE` | `mov [esi+0x24],0xFFFFFFF0` | **`+0x24` = vx 初值 = -16** |
| `0x40D9B5` | `mov [esi+0x28],ebx` | **`+0x28` = vy 初值 = 0** |
| `0x40D9B8` | `mov [esi+0x2C],ebx` | **`+0x2C` = t 初值 = 0** |

公共头（`0x430450`，`0x43A817` 调用）已写入：`[+4]=p[0]=x0`、`[+8]=p[1]=y0`、`[+0x14]=p[2]=type`、
`[+0x34]=1`（存活字节）、`[+0x38]=0x45A0E0([+0x3C])`（申请显示节点并尾插）、`[+0x3C]=p[0x10]=queue+4`。

`0x43AC30`（`0x40D94E` 调用，`ret 4`）随后按 `type&0xFF` 填一族共享字段：

```
idx  = [ent+0x14] & 0xFF                       ; 0x43AC3F/0x43AC42 → 2
rec  = 0x498000 + idx*10 - 10                  ; 0x43AC47/0x43AC4A → 0x49800A
[+0x0C] = byte  [rec+0]          = 0x18  (=24) ; 0x43AC4A/0x43AC52
[+0x18] = word  [rec+2] ? : -1   = 1           ; 0x43AC55..0x43AC68 （0 → -1，本型非 0）
[+0x58] = (s16) word [rec+4]     = 0x0180=384  ; 0x43AC6D/0x43AC71
rect    = ( word[rec+6], word[rec+8], +2*s-1, +2*s-1 ) = (48,0,95,47)   ; 0x43AC7C..0x43AC95
node[+4..+0x10] = rect                          ; 0x43ACAD..0x43ACB8
[+0x10] = 1 (byte)                              ; 0x43ACBE/0x43ACC0
node[+0] = 2                                    ; 0x43ACC3 ★ **层号 = 2（硬编码）**
node[+0x14] = x - s ; node[+0x18] = y - s       ; 0x43ACD5..0x43ACDC (=x-24, y-24)
node[+0x1C] = 1                                 ; 0x43ACEE（可见）
```

`0x498000` 的记录布局（10 字节，`[+1]` 无人读，26 条全 0）：
`[0]`b 半径 `[2]`w `+0x18` `[4]`s16 `+0x58` `[6]`w srcx `[8]`w srcy。
本型实值：`18 00 | 01 00 | 80 01 | 30 00 | 00 00`。

## 3. 行为函数 `0x40E100`（`0x40E100`–`0x40E1ED`，`ret`，`ecx=ent`，返回 `al`）

整个函数 74 条指令，无循环、无外部状态、只读写本实体 + 显示节点 + 一次 `0x40213F` 调用。

```c
bool __thiscall beh_40E100(Ent* e)          // esi = e（0x40E101）
{
  int t = e->dw2C;                          // 0x40E103
  // ── 段 1：速度积分（四个互斥时间窗，窗口是 [a,b) ）
  if (t >= 0x14 && t < 0x28) {              // 0x40E106/0x40E10B
      e->dw28 += e->dw20;                   // 0x40E110..0x40E118
  } else if (t >= 0x28 && t < 0x3C) {       // 0x40E11F/0x40E124..0x40E12C
      e->dw28 -= e->dw20;
  } else if (t >= 0x8C && t < 0x9C) {       // 0x40E131..0x40E14E
      e->dw24 += 1;  e->dw28 += e->dw20;
  } else if (t >= 0x9C && t < 0xAC) {       // 0x40E15A..0x40E170
      e->dw24 += 1;  e->dw28 -= e->dw20;
  }                                         // t < 0x14 / [0x3C,0x8C) / >=0xAC：不变
  // ── 段 2：位移（算术右移，向 -∞ 取整）
  int x = e->dw04 + ((e->dw24 + 2) >> 2);   // 0x40E173..0x40E17F/0x40E184
  int y = e->dw08 + ((e->dw28 + 2) >> 2);   // 0x40E187..0x40E192/0x40E199
  e->dw04 = x;  e->dw08 = y;
  // ── 段 3：到达 x==400 且 param==1 → 生成事件（§8）
  if (x == 0x190 && e->dw1C == 1)           // 0x40E194/0x40E19E/0x40E1A2
      sub_43B070(e, 0);                     // 0x40E1A4/0x40E1A8 = 0x40213F
  // ── 段 4：计时器 + 显示节点定位
  e->dw2C = t + 1;                          // 0x40E1AD..0x40E1B7
  node->dw14 = x - 0x18;                    // 0x40E1B0/0x40E1B4/0x40E1C1..
  node->dw18 = y - 0x18;                    // 0x40E1BA/0x40E1C2..0x40E1D0
  // ── 段 5：存活判定
  return (e->dw18_flag != 0) && (x < 0x2A8); // 0x40E1D3..0x40E1ED（+0x18 是有符号 dword）
}
```

要点（每条都有地址）：

1. **先改速度、再位移、最后 `t++`**：`t` 在 `0x40E1B3` 才自增，故 `t` 值 = 已执行过的帧数。
2. 位移用的是 `(+2)>>2`，即把 dword 速度当 **16 倍定点** 使用（vx=-16 → -4 px/帧）。
3. `x-0x18`/`y-0x18` 里的 `0x18` 是**硬编码**（`0x40E1B4`/`0x40E1BD` 立即数），
   不是读 `[ent+0x0C]`；本型两者恰好都等于 24（表 `[0]`）。
4. `node[+0x14/+0x18]` 用 `0x45A690`（`0x401753` = **恒等函数**，`eax,edx` 原样返回）写入，
   不构成任何坐标变换（与 `docs/p4_beh_23000003.md` 的更正一致）。
5. `x` 与 `0x190`、`0x2A8` 的比较：`0x40E194 je`、`0x40E1E1 jge` = **有符号**比较
   （`jl/jge`），实测 x 不会变负，等价位图。
6. 返回 0 的两种情形：`[ent+0x18]==0`，或 `x >= 680`（`0x40E1DA`/`0x40E1E1`）。

### 3.1 字段一览（本函数触及的全部字段）

| 字段 | 类型 | 读/写 | 地址 | 语义（本型） |
|---|---|---|---|---|
| `+0x04` | dword | R/W | `0x40E176`, `0x40E184` | x（中心，屏幕坐标） |
| `+0x08` | dword | R/W | `0x40E181`, `0x40E199` | y（中心） |
| `+0x18` | dword | R | `0x40E1D3` | 存活门（表值，本型 = 1；0 会被 0x43AC30 改成 -1） |
| `+0x1C` | dword | R | `0x40E19E` | param（payload[0xC]） |
| `+0x20` | dword | R | `0x40E110`, `0x40E124`, `0x40E142`, `0x40E164` | 纵向加速度 ±1 |
| `+0x24` | dword | R/W | `0x40E13F..0x40E14B`, `0x40E161..0x40E16B`, `0x40E173` | vx（16 倍定点，初值 -16） |
| `+0x28` | dword | R/W | `0x40E113..0x40E118`, `0x40E127..0x40E12C`, `0x40E145..0x40E14E`, `0x40E167..0x40E170`, `0x40E189` | vy（初值 0） |
| `+0x2C` | dword | R/W | `0x40E103`, `0x40E1B7` | 帧计时器 t |
| `+0x38` | ptr | R | `0x40E1C7`, `0x40E1CD`, `0x40E1D0` | 显示节点 |
| `node+0x14` | dword | W | `0x40E1CD` | 屏幕 x = x-24 |
| `node+0x18` | dword | W | `0x40E1D0` | 屏幕 y = y-24 |

**不读**：`+0x0C`（半径）、`+0x10`、`+0x34`、`+0x3C`、`+0x58`——这些只由 ctor / 碰撞 / 析构用。

## 4. 数值推演（由 §3 公式直接算出，非拟合）

初值代入 `vx=-16, vy=0, t=0`，`a = [ent+0x20]`（`y0<=240 → -1`，否则 `+1`），
`vx` 在 `t=140..155` 与 `t=156..171` 各 `+1`（共 +32 ⇒ `t>=172` 时 `vx=+16`）。

| t | 事件 |
|---|---|
| 0..19 | `x -= 4/帧`，vy 不变（0） |
| 20..39 | `vy += a` 每帧 ⇒ 第 40 帧 vy=±20；y 开始平移（每帧 `(vy+2)>>2`） |
| 40..59 | `vy -= a` ⇒ `t=60` 时 vy=0；y 停在峰值（相对 y0：+105 / -95） |
| 60..139 | 纯横移 `x -= 4/帧`（x 从 424 到 104） |
| 140..155 | 每帧 `vx+=1`（-16→0），步长 -4→0，x 从 100 缓到 76（最小值） |
| 156..171 | 每帧 `vx+=1`（0→+16），步长 0→+4，x 从 76 回 116，且 `vy += -a`×16 让 y 继续走 |
| 172.. | 恒速 `x += 4/帧` |
| x 到达 680 | 该帧返回 0 → 自毁（`t≈313`，从 664 出生起算） |

两个实例（关 1 实数据 `x0=664`）：

| t | `y0=280`(a=+1)：x, y, dst | `y0=200`(a=-1)：x, y, dst |
|---|---|---|
| 0 | 660, 280 → (636,256) | 660, 200 → (636,176) |
| 39 | 504, 335 → (480,311) | 504, 150 → (480,126) |
| 59 | 424, 385 → (400,361) | 424, 105 → (400,81) |
| 139 | 104, 385 → (80,361) | 104, 105 → (80,81) |
| 155 | 76, 421 → (52,397) | 76, 73 → (52,49) |
| 172 | 116, 453 → (92,429) | 116, 45 → (92,21) |

- `param==1` 时 **x 恰好两次等于 400**：`t=65`（左行途中）与 `t=243`（右行途中）。
  原因是步长始终是 4 的整数倍（`vx` 为 4 的倍数时 `(vx+2)>>2` = `vx/4` 整），
  `x ≡ 664 ≡ 0 (mod 4)` 而 `400 ≡ 0 (mod 4)`，所以是精确命中而不是"接近触发"。
  ⇒ **每个 param==1 的个体会生成 2 枚 `0x31000001`**；param==0 的个体一枚也不生成。
- 纵向峰值出现在 `t≈59`（a=+1: +105 px，a=-1: -95 px）；第二段竖直位移（`t=140..171`）
  再叠 +68 / -60，即 `t=172` 时相对 y0 共 +173 / -155。

## 5. 屏幕裁剪与贴屏细节（`0x45A170` 内部，本型必经）

渲染 pass `0x458EF0` 对 `0x4AD43C` 的调用是 `0x458F04 mov ecx,0x4AD43C; 0x458F09 call 0x402531`
（`0x402531`→`0x430840` = `add ecx,4; jmp 0x45A170`）。pass 顺序：
`0x4AD55C → 0x4AD4CC → **0x4AD43C** → 0x4AD49C → 0x4AD40C → 0x4AD46C → 0x4AD4FC`。
（tick pass `0x458E70` 的对应顺序：`0x4AD55C → 0x4AD40C → 0x4AD46C → **0x4AD43C** → 0x4AD49C → 0x4AD4CC → 0x4AD4FC → 0x4AD52C`，
`0x458E8E/0x458E93 call 0x401929`→`0x43BC70`。）

`0x45A170` 对每个节点做（本型相关分支）：

```
l=[node+4] t=[node+8] r=[node+0xC] b=[node+0x10]     ; 0x45A19D..0x45A1B0 → (48,0,95,47)
x=[node+0x14] y=[node+0x18]                          ; 0x45A1B3..0x45A1C0
x2 = x - l + r ; y2 = y - t + b                       ; 0x45A1C0..0x45A1CB
if (x < clipL) { srcL += clipL-x; x = clipL }         ; 0x45A1DE..0x45A1F3
if (x2 > clipR) srcR += clipR - x2                    ; 0x45A1F7..0x45A206
if (y < clipT) { srcT += clipT-y; y = clipT }         ; 0x45A20A..0x45A223
if (y2 > clipB) srcB += clipB - y2                    ; 0x45A227..0x45A236
if (srcL < srcR && srcT < srcB) 0x44D010(...)         ; 0x45A23A..0x45A264
```

裁剪窗 = 显示表对象 `[queue+4]` 的 `+4/+8/+0xC/+0x10`，初值在 **`0x459F70`** 里写死
`(0,0,640,480)`（`0x459F7B/0x459F7E/0x459F81/0x459F88`），由队列基类 ctor `0x430740`
（`0x43075D lea ecx,[esi+4]; 0x430760 call 0x401E65`）在**构造队列 `0x4AD43C`**时调用：
管理器 `0x4AA7B0` 的 ctor `0x456A20` → `0x456AE5 lea ecx,[esi+0x2C8C]; call 0x4013B1`
→ `0x43BB70`：`0x43BB73 call 0x401618(=0x430740)` → 之后 `0x43BB7A mov [esi],0x498750`、
清 `+0x28/+0x2C`。`0x430740` 末尾 `0x430775 call 0x4011D1(=0x430800)` 再走一次
`0x45A070`（`=0x430800` 的目标）分配头/尾哨兵。
⇒ **裁剪窗确为全屏 `(0,0,640,480)`**，所以本型只有贴边时才被裁。

实际 blit（`0x44D010`，`ret 0xC`，`this=0x4AA7B0` 层管理器）：

| 参数 | 来源 | 值 |
|---|---|---|
| `this` | `0x45A25F` | `0x4AA7B0` |
| arg1 `&dst{int x,int y}` | `0x45A259 lea eax,[esp+0x18]` → `0x45A25E push` | `(x-24, y-24)` |
| arg2 `layer` | `0x45A252 mov edx,[esi]` → `0x45A25D push` | **2** |
| arg3 `&src{l,t,r,b}` | `0x45A254 lea ecx,[esp+0x1C]` → `0x45A258 push` | `(48,0,95,47)` 经上述裁剪 |
| flags | `0x44D028 push 0x11` | `0x11` = SRCCOLORKEY |

`0x44D010` 体内：`eax=[mgr+0x10]`（层数组）→ `ecx=[mgr+layer*4+0x14]`（层 2 表面）→
`edx=[eax]`（表面 vtable）→ `call [edx+0x1C](surf, dst.x, dst.y, rect, 0x11)`（`0x44D010..0x44D03E`）。

**贴边举例**（`x0=664` 首帧，`x=660`）：`dst=(636,256)`，`x2=636-48+95=683>640`
⇒ `srcR = 95+(640-683) = 52`，实际只贴 `(48,0,52,47)` 4 列到 `(636..639, 256..303)`。

## 6. 显示节点（`0x28` 字节，`0x45A0E0` 返回）

| 偏移 | 值 | 写入点 |
|---|---|---|
| `+0x00` | 2（层） | `0x43ACC3` |
| `+0x04` | 0x30 (48) | `0x43ACAD` |
| `+0x08` | 0 | `0x43ACB2` |
| `+0x0C` | 0x5F (95) | `0x43ACB5` |
| `+0x10` | 0x2F (47) | `0x43ACB8` |
| `+0x14` | x-24（每帧） | `0x43ACE2`（出生）/`0x40E1CD`（每帧） |
| `+0x18` | y-24（每帧） | `0x43ACE6` / `0x40E1D0` |
| `+0x1C` | 1（可见字节） | `0x43ACEE`；死亡时 `0x43BC9A` 清 0 |
| `+0x20/+0x24` | 前驱/后继 | `0x45A0E0/0x45A130` |

## 7. 生命期 / 销毁

队列 `0x4AD43C` 的 tick `0x43BC70`（`= thunk 0x401929`）：

```
0x43BC78 esi = [queue+0x28]              ; 实体链头
0x43BC81 if (byte[esi+0x34] == 0) → 0x43BCA4 摘除
0x43BC88 call 0x40131B(=0x43AD40 → jmp [ecx+0x40])   ; 行为，返回 al
0x43BC8F al != 0 → 保留
0x43BC91..0x43BC9A 死亡当帧：byte[ent+0x34]=0, byte[ent+0x10]=0, byte[node+0x1C]=0
0x43BCA4 push prev; push ent; call 0x4010F0(=0x43BED0)   ; 立刻摘链
```

`0x43BED0(ent, prev)`：`[ent+0x44]`（next）接到 `prev+0x44`（无前驱则写 `[queue+0x28]`），
`next==0` 时 `[queue+0x2C]=prev`，然后 `vtable[0](ent,1)`（`0x43BEF5..0x43BEF9`）：
`0x49874C[0] = 0x401F0A` → `0x43ABE0` → `0x43AC10`（重设 vtable）→ `0x4304F0`
（摘显示节点 + `0x47C7E9` 释放 0x5C 实体）。

⇒ **返回 0 的那一帧就摘链 + 释放，且发生在渲染 pass 之前，因此不会画出死亡帧。**
另外 `0x43BC81` 的 `[ent+0x34]` 是"已死"标记：`0x458D60`（阶段净化）走
`0x43BC40 → 0x401FEB(=0x43BF20) + 0x4011D1(=0x430800)` 把整条队列清空重挂。

## 8. `x == 0x190 && param == 1`：生成 `0x31000001` 到队列 `0x4AD49C`

`0x40213F` = `0x43B070`（`ret 4`，`ecx=ent`，实参 `0`）：

```
0x43B07F esi = [0x56CC8C] - [ent+4]        ; 屏幕参照点 - 实体 x
0x43B088 edi = [0x56CC90] - [ent+8]        ; 参照点 - 实体 y
0x43B093 0x401FB4(ent, arg=0) → ebx  ; =0x43AF90：arg==0 时取 [ent+0x58]=384 → sar ebx,4
0x43B09D..0x43B0C2 与 0x45AA80(dx,dy) 的返回值相乘得 (dx,dy) 到 [esp+0x10]/[esp+0x14]；两者都 0 则跳过
0x43B0D3 0x40113B(ent,&vec) → eax = **0x43B020(ent)** = 出生类型号
0x43B0E6 0x4023C4(=0x430400) 打包：payload[0]=x, [4]=y, [8]=eax, [0xC]=栈残留
0x43B105 0x401861(=0x435440)(queue=0x4AD49C, payload)   ; 入队
```

`0x43B020` 对 `type&0xFF000000` 分族（`0x43B020`–`0x43B046`）：

| 族 | 返回类型号 |
|---|---|
| `0x25000000` | 走 `0x43B04D` 分支（不在本型范围） |
| `0x26000000` | 走 `0x43B047` 分支 |
| 其它（含 **本型 0x23000000**） | `((-(type-0x27000000)) ? -1 : 0) & 0xF7 + 0x3100000A` = **`0x31000001`** |

代入 `0x23000002`：`0x23000000-0x27000000 = 0xFC000000` → `neg` → 非 0 ⇒ `sbb eax,eax = -1`
→ `and al,0xF7` → `0xFFFFFFF7` → `+0x3100000A` = **`0x31000001`**（截断到 32 位）。

⇒ **param==1 的个体每帧检查 x 是否恰为 400；命中即在自身 (x,y) 处向 `0x4AD49C` 生成一枚
`0x31000001`**（`0x435440` 会先做 `[0x56CCB2]`/族 `0x32` 的过滤，本型不触发该过滤）。
生成物自身的 ctor/行为不在本文范围（未解，见 §10）。

## 10. 未解 / 待定

1. **`0x31000001` 是什么**：本文只定案"生成它的类型号与入口"（`0x43B020`/`0x430400`/`0x435440`）。
   该类型的 ctor（`0x43BDC0`→`0x43A7F0` 家族以外？`0x435440` 的 malloc 尺寸与 ctor 未逐条解）、
   行为、以及它是否就是"得分道具"，均未解。
   （`0x430400` 的第 5 个 dword `payload[0xC]` 在 `0x43B070` 里没有实参，是栈残留——`0x430430` 只写 4 项。）
2. **`[ent+0x58]=384` 的用途**：唯一读点是 `0x43AF9A`（`0x43AF90`，`arg==0` 时取它），
   随后 `0x43AFB1` 可能 `esi*=2`（当 `0x4AB5B0` 查值 == 3）、`0x43AFB3` 再与 `0x56CCB0` 比较。
   它最终只影响 `0x43B070` 内部那个"方向向量是否全 0"的门（`0x43B0C6`），本型从不全 0
   ⇒ 对生成与否无影响。384 这个数量本身的语义（"强度"？"伤害"？）未定。
3. **`[ent+0x18]` 的语义**：本型 = 1（表值）。行为只 `test`；命中处理 `0x43CCC0` 的默认分支
   `0x43D0BF`：`if ([ent+0x18]==0) byte[ent+0x10]=0`——**不清零 `+0x18`、不减血**。
   未找到任何把本型 `+0x18` 改成 0 的写点 ⇒ 本型的存活门恒真，`x>=680` 是唯一自毁条件。
4. **`[ent+0x10]`（"可命中"字节）**：`0x43ACC0` 置 1；碰撞 `0x4306C0`（thunk `0x401843`）
   第 1 条就 `if ([ent+0x10]==0) return 0`，再用 `[ent+0x0C]`(24) 与对方半径做菱形判定
   （`0x4306F4..0x430706`）。也就是说**这些背景贴片参与弹-实体碰撞**（调用方
   `0x43C0F0` 中的 `0x43C105..0x43C128`，命中后 `0x43C135 call 0x401FDC`）。
   但默认命中分支对本型什么都不做（见第 3 条），实机是否"子弹被吃掉"未验证。
5. **`0x4AD43C` 与 `0x4AD40C` 的分工**：本文只证明 `0x23000002` 在 `0x4AD43C`（`0x43BDC0`）。
   `0x43BDC0` 的其余 183 个调用点属于哪些类型，未逐个归类。
6. `0x45A170` 里 `0x45A259 lea eax,[esp+0x18]` 用的是"push 后 esp 偏移"，
   等价于 `&[base+0x14]`（= x）；本文按计算结果标注，若后续有人改写该函数请保持此结论。

## 11. 复刻 checklist（照这个顺序写就不会错）

1. 出生：`x=payload[0]`、`y=payload[1]`、`t=0`、`vx=-16`、`vy=0`、
   `a = (y<=240 ? -1 : +1)`、`param=payload[0xC]`；显示节点 `layer=2`、`src=(48,0,95,47)`、可见=1。
2. 每帧（60 Hz，先于渲染）：
   - 按 §3 的四段窗改 `vx/vy`；
   - `x += (vx+2)>>2`；`y += (vy+2)>>2`（**向 -∞ 取整**，Python 用 `(v+2)>>2`，C 用 `>>`）；
   - `x==400 && param==1` → 生成 `0x31000001` 到 `0x4AD49C`；
   - `t += 1`；`dst = (x-24, y-24)`；
   - `if ([+0x18]==0 || x>=680) 当帧摘除（不渲染）`。

   只有贴到 `(0,0,640,480)` 之外时才按 §5 的公式裁源矩形（左右/上下各自独立）。
