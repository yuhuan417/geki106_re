# 页4 实体公共头 `0x40180C` + `0x23` 族子 ctor 字段表（定案）

> 本文只做**字段/构造**，不做行为函数分析。
> 依据：`geki106.exe`（基址 `0x400000`，`pefile` 内存映射 + `capstone` 反汇编 + 原始字节扫描）。
> 反汇编工具：本仓库 `re_dis.py`（`R.dis()/R.xrefs()/R.insns`）。
> 记号：`ent` = 实体基址（this），`p` = payload 指针（ctor 的栈参数）。

---

## 0. 速览：任务前提的 3 处校正

| # | 前提 | 实证 | 依据 |
|---|---|---|---|
| 1 | `0x40180C` 是"公共初始化"本体 | **半对**。`0x40180C` 只是 `jmp 0x430450`（纯跳转 thunk，`0x401811/0x401816/…` 是一整片 thunk 表）。真正代码在 **`0x430450`** | `0x40180C` 处 5 字节 `E9 …`，目标 `0x430450` |
| 2 | `0x4013D9` 是 thunk，可能形如 `mov ecx,[esp+4]; jmp X` | **错**，它就是**裸 `jmp 0x40D940`**（无 ecx 重装）。`ecx` 由调用方 `0x43A88D mov ecx,esi` 提供 | `0x4013D9` 目标 `0x40D940` |
| 3 | `0x40180C` 只写"若干 dword" | **它做了 3 件额外的事**：写 vtable（`0x498734`）、写存活字节 `+0x34=1`、**登记显示节点** `[ent+0x38]`（`0x45A0E0` 分配并链入显示表） | `0x43045E/0x430486/0x43048A-0x43048F` |

补充：`0x23` 族 ctor `0x40D940` 的**第一件事**不是分派，而是调用 `0x43AC30` 查 **`0x498000` 10 字节/条 的属性表**，把尺寸/半径/HP/源矩形按 `type & 0xFF` 一次填好（见 §2.2）。

## 1. `0x40180C` → `0x430450` 逐条

### 1.1 函数界定

| 项 | 值 |
|---|---|
| thunk | `0x40180C`：`E9` 相对跳转 → `0x430450` |
| 代码区间 | `0x430450` – `0x430499`（含结尾 `ret 4`）= **74 字节** |
| `\xcc\xcc\xcc` 界定 | 从 `0x430450` 起首个 `cc cc cc` 在 `0x4304A0` ⇒ 含 6 个 `nop` 对齐填充共 **0x50 = 80 字节** |
| 调用约定 | `__thiscall`，`ecx = ent`，栈上 1 个参数（payload），`ret 4` |
| 返回 | `eax = esi = ent`（this）。调用方 `0x43A817` 丢弃返回值（`0x43A81C` 立刻重读 `[esi+0x14]`） |
| 邻居 | `0x4304C0` = 虚析构（vtable[0]，`call 0x402374`→`0x4304F0` 析构体 + 条件 `free 0x47C7E9`）；`0x4304F0` = 析构体：`[ecx]=0x498734` 后 `0x4013F7`→`0x45A130(mgr, [ent+0x38])` 摘除显示节点 |

### 1.2 逐条伪代码

```c
void* __thiscall sub_430450(void* ent /*ecx*/, int* p)
{
  ent->vtbl      = 0x498734;      // 0x43045E  基类 vtable（8 项，[0]=0x4304C0 析构）
                                  //           ★ 随后被 0x43A82C 覆盖成 0x49874C
  ent->dword3C   = p[4];          // 0x430464/0x43046A  = payload+0x10（显示表 mgr 指针）
  memset(&ent->dw04, 0, 0x38);    // 0x43046F rep stosd ecx=0xE（14 dword）
                                  //   → 清 +0x04..+0x3B（含 +0x34 存活、+0x38 节点指针）
  ent->dw04      = p[0];          // 0x430473 / 0x430477   x（中心）
  ent->dw08      = p[1];          // 0x43047A / 0x43047D   y（中心）
  ent->dw14      = p[2];          // 0x430480              type（族分派键）
  ent->b34       = 1;             // 0x430486              存活字节
  ent->dw38      = sub_45A0E0(ent->dw3C);  // 0x430483/0x43048A/0x43048F
                                  //   = 向显示表申请并链入 1 个 0x28 字节显示节点
  return ent;                     // 0x430492  ret 4
}
```

**注意 payload 的读取顺序**：`+0x10` 先读（`0x430464`，在 `rep stosd` 之前，因为 `+0x3C` 不在清零范围内），
`+0x00/+0x04/+0x08` 在清零之后读。

### 1.3 它到底写了哪些偏移

| 偏移 | 写什么 | 指令 |
|---|---|---|
| `+0x00` | `0x498734`（基类 vtable） | `0x43045E` |
| `+0x04` .. `+0x3B` | 全部清 0（14 dword） | `0x43046F rep stosd` |
| `+0x04` | `p[0]` | `0x430477` |
| `+0x08` | `p[1]` | `0x43047D` |
| `+0x14` | `p[2]` = type | `0x430480` |
| `+0x34` | byte = 1（存活） | `0x430486` |
| `+0x38` | 显示节点指针（`0x45A0E0` 返回） | `0x43048F` |
| `+0x3C` | `p[4]`（显示表 mgr） | `0x43046A` |

**不写**：`+0x40`（行为入口）、`+0x44` 之后（`+0x44/+0x48/+0x4C/+0x50/+0x54/+0x58`）。
这些由 `0x43A7F0` 在 `0x430450` 返回之后写（`0x43A832..0x43A846`），行为入口则由各族子 ctor 写。

**结论（对应问题 1）**：`0x40180C` 写 **3 个 payload dword**（`+0x00→+0x04`、`+0x04→+0x08`、`+0x08→+0x14`）
外加 **1 个 payload dword 到 `+0x3C`**（共 4 个）；**同时**写 vtable、存活字节、显示节点指针；返回 `this`。

### 1.4 显示节点（`0x45A0E0`）与本 ctor 的关系

`0x45A0E0`（`__thiscall`，`ecx = p[4]` 显示表对象）：
`malloc(0x28)` → 尾插到链（节点 `+0x20` = prev、`+0x24` = next、`[mgr+0x1C]` = 尾、`[mgr+0x20]` = 计数）→ **返回新节点**。
`0x45A0E0` **不**初始化节点内容，只分配；节点字段由各 ctor 自己写：

| 节点偏移 | 含义 | 依据 |
|---|---|---|
| `+0x00` | **贴图源层号** | `0x45A25D` 把它作第 2 参传给 `0x44D010`（`0x44D01B mov ecx,[this+layer*4+0x14]` 取层表面） |
| `+0x04..+0x13` | 源矩形 `{l,t,r,b}` | `0x45A19A..0x45A1B2` 逐分量读 |
| `+0x14` | 目标 x（左上） | `0x45A1B6` |
| `+0x18` | 目标 y（左上） | `0x45A1BD` |
| `+0x1C` | byte 有效位（0 = 不画） | `0x45A18C test al,al` |
| `+0x20` / `+0x24` | prev / next | `0x45A0FE..0x45A10A` |

链两端各有一个 **哨兵节点**（`0x45A070` 分配，`[mgr+0x18]`=头哨兵、`[mgr+0x1C]`=尾哨兵），
渲染 `0x45A170` 从 `[[mgr+0x18]+0x24]` 开始按 `+0x24` 走，遇 `next==0` 停 ⇒ 尾哨兵不参与绘制。
析构 `0x4304F0` → `0x45A130(mgr, node)` 断链并 `free`。

> **旁证**：`0x43A371`（队列 tick）在实体死亡时执行
> `ent->b34 = 0; ((Node*)ent->dw38)->b1C = 0;` —— 同时确认 `+0x34` 存活与 `+0x38` 是"本实体的"节点。

## 2. `0x4013D9` → `0x40D940`（`0x23` 族子 ctor）

### 2.1 签名与结构

| 项 | 值 |
|---|---|
| thunk 目标 | `0x4013D9`: `jmp 0x40D940`（裸跳转） |
| 调用点 | `0x43A88C push edi` / `0x43A88D mov ecx,esi` / `0x43A88F call 0x4013D9`；`edi` = payload |
| 签名 | `void __thiscall sub_40D940(ent, int* p)`，`ret 4` |
| 参数位置 | `p = [esp+0x3C]`（`sub esp,0x28` + 4 个 push 之后，故为 `0x28+0x10+4`） |
| 长度 | `0x40D940` – `0x40DE95`（`ret 4`），跳表 `0x40DE98`（26 项 ×4 = 0x68），`0x40DF00` 起 `int3` |
| 分派 | `eax = ent->type & 0x2F000000` 已由 `0x43A7F0` 判成 `0x23000000`；这里再 `eax = type + 0xDCFFFFFF`，`cmp eax,0x19 / ja 默认` ⇒ 索引 = `type - 0x23000001`（0..25），`jmp [eax*4+0x40DE98]` |

### 2.2 第 0 步：属性表初始化 `0x43AC30`（**所有 26 支共用**）

`0x40D949 push 0x498000` / `0x40D94E call 0x402455`(=`0x43AC30`)，该函数 `ret 4`，故栈自动平衡。

```c
void __thiscall sub_43AC30(ent, const void* tbl /*=0x498000*/)
{
  int i = ent->type & 0xFF;                 // 0x43AC3F/0x43AC42
  char* r = tbl + 10*i - 10;                // 0x43AC47 lea eax,[eax+eax*4]; 0x43AC4A [ecx+eax*2-0xa]
  ent->dw0C = r[0];                         // 0x43AC52  ★ 半径（byte，零扩展）
  ent->dw18 = *(u16*)(r+2) ? *(u16*)(r+2) : -1;   // 0x43AC55..0x43AC68
  ent->dw58 = *(s16*)(r+4);                 // 0x43AC6D/0x43AC71
  // 显示节点（ent->dw38）：
  node->dw00 = 2;                           // 0x43ACC3  源层 = 层2（48×48 精灵图集）
  node->rect = { (s16)r[6], (s16)r[8],      // 0x43AC8C..0x43AC95 → 0x40238D→0x45A750
                 (s16)r[6]+2*r[0]-1, (s16)r[8]+2*r[0]-1 };  // l=srcx, t=srcy, r=l+2s-1, b=t+2s-1
  node->dx = ent->x - s;  node->dy = ent->y - s;   // 0x43ACD7 → 0x401753→0x45A690；s = r[0]
  ent->b10 = 1;                             // 0x43ACC0  ★ 参与碰撞标记
  node->b1C = 1;                            // 0x43ACEE  有效
}
```

- 表基址 `0x498000`，**10 字节/条**，共 26 条（见附录 A），索引 = `type & 0xFF`（1..26）。
- `=> 实体的 `+0x0C` = 半径、`+0x18` = 表值(0→-1)、`+0x58` = 表值(有符号 word)`，且源矩形/目标点/层号
  全部来自这张表 —— **7 个类型在本步之后的显示节点只有"源矩形"不同**。

### 2.3 第 1 步：按 type 分支（与 7 个目标类型相关的部分）

`p[k]` 记 payload 第 k 个 dword。`p[3]` 在多数分支被原样存进实体（是个"参数块指针"，见 `0x23000006/0x23000016` 会解引用 `p[3]`、`p[3]+4`、`p[3]+8`），7 个目标类型**都不解引用**。

| type | 分支 | 写入（`[ent+…] = 值`） |
|---|---|---|
| `0x23000001` | `0x40D96D` | `+0x40 = 0x401C44`；`+0x1C = 0` |
| `0x23000002` | `0x40D985` | `+0x40 = 0x401FF0`；`+0x1C = p[3]`；`+0x20 = (y <= 0xF0) ? -1 : +1`；`+0x24 = -16`；`+0x28 = 0`；`+0x2C = 0` |
| `0x23000003` | `0x40D9C5` | `+0x40 = 0x401B1D`；`+0x1C = p[3]`；`+0x20 = -4`；`+0x24 = 0` |
| `0x23000004` | `0x40D9EE` | `+0x40 = 0x40118B`；`+0x1C = 0`；`+0x20 = -30`；`+0x24 = p[3]` |
| `0x23000005` | `0x40DA17` | `+0x40 = 0x401BD1`；`+0x1C = 0`；`+0x20 = 0`；`+0x24 = 0`；`+0x28 = 0`；`+0x2C = p[3]` |
| `0x23000007` | `0x40DA71` | `+0x40 = 0x402180`；`+0x1C = p[3]`；`+0x20 = 0` |
| `0x23000008` | `0x40DA93` | `+0x40 = 0x401528`；`+0x1C = 0`；`+0x20 = -8` |

三个细节：

1. `0x23000002` 的 `+0x20` 是**按 y 决定的方向**：`xor edx,edx; cmp y,0xF0; setle dl; dec edx; and edx,2; dec edx`
   ⇒ `y<=240` 得 `-1`，否则得 `+1`（`0x40D98E..0x40D9A5`）。
2. `0x23000008` 只写 `+0x1C/+0x20`，`+0x24..+0x30` 保持 `0x430450` 的清零值（与其它支不同，注意别漏初始化）。
3. `0x23000005` 与 `0x23000006` **共用行为** `0x401BD1`（→ `0x40E520`），区别只在 `+0x1C..+0x2C` 的
   取值方式：`05` 存 `p[3]`（指针），`06` 解引用成 `*p[3]` / `*(p[3]+4)`（`0x40DA4E..0x40DA5F`）。

**这 7 支都不碰显示节点**（层/矩形/目标点/有效位全由 §2.2 决定），
也不写 `+0x10`、`+0x18`、`+0x58`、`+0x0C`。

## 3. 实体字段总表（0x00..0x5C，尺寸 0x5C 字节）

「写入地址」列：`430450` = 公共头，`43A8xx` = `0x43A7F0` 主干，`43AC30` = 属性表，`40D9xx/40DAxx` = 本族 ctor 分支。

| 偏移 | 尺寸 | 写入地址 | 值来源 | 语义（推测项已标注） |
|---|---|---|---|---|
| `+0x00` | dword | `0x43045E` `0x43A82C` | `0x498734` → `0x49874C` | vtable。基类 8 项（`[0]`=析构 `0x4304C0`），派生 3 项（`0x43ABE0/0x43BBA0/0x43BF80`） |
| `+0x04` | dword | `0x430477` | `p[0]` | **x（中心坐标）** —— `43AC30` 用它算 `node->dx = x - s`；行为里直接被当坐标用（`0x40E079 dec [esi+8]` 等） |
| `+0x08` | dword | `0x43047D` | `p[1]` | **y（中心坐标）** |
| `+0x0C` | dword | `0x43AC52` | 表 `r[0]`（byte） | **半径/半尺寸**。7 型全为 `24` ⇒ 命中圈 48、精灵 48×48。碰撞函数 `0x43BFDC` 把它当第 3 参传 `0x401843` |
| `+0x10` | byte | `0x43046F`(清0) `0x43ACC0`=1 | 常量 | **参与碰撞标记**：`0x43BFFC mov al,[esi+0x10] / test al,al / je` 跳过不参与碰撞的实体。`0x23000001` 支另在 `0x43A8B1` 也写 1；`0x23000011` 支（`0x40DC03`）写 0（不参与碰撞） |
| `+0x11..+0x13` | 3 byte | `0x43046F` | 0 | 未用（清零） |
| `+0x14` | dword | `0x430480` | `p[2]` | **type**（完整 32 位；`&0x2F000000` = 族，`&0xFF` = 属性表索引） |
| `+0x18` | dword | `0x43AC68` | 表 `r[2]`（word，`0` ⇒ `-1`） | **HP / 寿命计数（推测）**：`0x23000007` 行为以 `([+0x18] != 0)` 作返回值（`0x40E862..0x40E86A`）；表值为 `-1` 表示"永不为 0"。7 型取值：`1 / 1 / 20 / 320 / 72 / 1 / 100` |
| `+0x1C` | dword | `0x40D9xx/0x40DAxx` | 分支常量 或 `p[3]` | **逐类型状态 #1**：`t1`=0（行为里当帧计时器 `0x40E073 inc`）；`t2/t3/t7`=`p[3]`；`t4/t5/t8`=0 |
| `+0x20` | dword | 同上 | 分支常量 或 `p[3]` | **逐类型状态 #2**：多为 ±1 方向或速度分量。`t2`=`±1`(y≤240→-1)、`t3`=`-4`、`t4`=`-30`、`t5`=`0`、`t7`=`0`、`t8`=`-8` |
| `+0x24` | dword | 同上 | 常量 或 `p[3]` | 状态 #3：`t1`=0、`t2`=`-16`、`t3`=`0`、`t4`=`p[3]`、其余未写 |
| `+0x28` | dword | 同上 | 常量 或 `p[3]` | 状态 #4：`t2`=`0`、`t5`=`0` |
| `+0x2C` | dword | 同上 | `p[3]` | 状态 #5：`t5`=`p[3]` |
| `+0x30` | dword | 同上 | — | 状态 #6：**7 个目标类型都不写**（仅 `0x23000015/16/17/1A` 支写） |
| `+0x34` | byte | `0x430486`=1 | 常量 | **存活字节**。死亡时 `0x43A374` 清 0，同时关显示节点 |
| `+0x38` | dword | `0x43048F` | `0x45A0E0(mgr)` | **显示节点指针**（不是 `+0x2C`）。节点布局见 §1.4；析构 `0x4304FD` 摘除 |
| `+0x3C` | dword | `0x43046A` | `p[4]` | 该实体所属**显示表对象**（`0x4AD4CC` 一类的全局；节点申请/释放在这里登记） |
| `+0x40` | dword | `0x40D9xx/0x40DAxx` | 分支常量 | **行为入口**。`0x446450`/`0x437920` = `jmp [ecx+0x40]`，`ecx`=ent，无栈参 |
| `+0x44` | dword | `0x43A843`(清0) | 0 | **队列 next**（`0x43A37C mov esi,[esi+0x44]`、`0x43A490` 摘链） |
| `+0x48` | dword | `0x43A83A`(清0) | 0 | 未定（本族不用） |
| `+0x4C` | byte | `0x43A83D`(清0) | 0 | 未定（本族不用） |
| `+0x50` | dword | `0x43A840`(清0) | 0 | 未定（本族不用） |
| `+0x54` | dword | `0x43A846`(清0) | 0 | 未定（本族不用） |
| `+0x58` | dword | `0x43A846`(清0) `0x43AC71` | 表 `r[4]`（**有符号** word） | **推测：速度（8.8 定点）**。7 型取值 `512 / 384 / 512 / -640 / 0 / 0 / 0`（= `2.0 / 1.5 / 2.0 / -2.5 / 0`），负值说明不是分数。`0x23000008` 行为读它 |

> payload 结构（由 `0x4023C4`/`0x43BDC0` 的调用点反推，至少 `0x14` 字节）：
> `{+0x00 x, +0x04 y, +0x08 type, +0x0C 参数指针, +0x10 显示表 mgr}`。

## 4. 7 个具体类型：差异项 + 行为入口

行为入口取自本族 ctor 里写 `[ent+0x40]` 的那条指令（左列是立即数，右列是 thunk 解引用后的真实地址）：

| type | `[ent+0x40]` 立即数 | 行为真实入口 | 表值 `(半径, +0x18, +0x58, srcx, srcy)` | ctor 差异（相对公共部分） |
|---|---|---|---|---|
| `0x23000001` | `0x401C44` | **`0x40E070`** | `(24, 1, 512, 0, 0)` | `+0x1C=0`，其余全 0 |
| `0x23000002` | `0x401FF0` | **`0x40E100`** | `(24, 1, 384, 48, 0)` | `+0x1C=p[3]`、`+0x20=±1`(y≤240→-1)、`+0x24=-16` |
| `0x23000003` | `0x401B1D` | **`0x40E230`** | `(24, 20, 512, 0, 0)` | `+0x1C=p[3]`、`+0x20=-4` |

## 7. 未解项

1. **`+0x18` 的递减/伤害点未定位**：本族 ctor 从表里取初值（`0`→`-1`），`0x23000007` 行为把它当存活判据，
   但 `.text` 里 `sub/dec [reg+0x18]` 的 3 处命中（`0x4380C3`、`0x4399DC`、`0x439A1F`）都用的是
   **显示节点的** `+0x18`（`eax = [esi+0x38]` 后再取），不是实体的。⇒ HP 语义仍是推测，扣血点待查（可能在碰撞命中 `0x401028` 里）。
2. **`+0x58` 语义**：表值有正有负（`512/384/-640/…`），判断为 8.8 定点速度，但无行为证据链（只有 `0x23000008` 读一次）。
3. **`+0x48 / +0x4C / +0x50 / +0x54`**：本族恒为 0，其它族的 ctor 是否用它、谁读，未查（`0x43A7F0` 只清零）。
4. **`+0x30`**：7 个目标类型不写，只有 `0x23000015/16/17/1A` 支写（`-64`/`0`/`0`/`y<<4`），语义未定。
5. **payload `+0x14` 及以后**：本族只用 `p[0..4]`；`0x430450` 读 `p[4]` 作显示表 mgr，但 `0x4023C4`
   类构造器的完整字段数（是否还有 `p[5]`）未逐条核对 —— 现阶段按 `0x14` 字节记。
6. **`0x498000` 表 `[1]` 字节**：26 条全为 0，本族 ctor 不读；是否有别的族/别的函数按不同 stride 读，未查。
7. **`0x4AD4CC` 与"显示表子对象"的 +4 偏移关系**：`0x430800/0x430840` 这两个 trampoline 都先 `add ecx,4`
   （`0x45A070`/`0x45A170` 的 `this` 是 `mgr+4`），而实体 ctor 走的是 `0x45A0E0`（`this = p[4]`，**不 +4**）。
   两者是否指向同一对象的不同视图（即 `p[4]` 存的其实是 `mgr+4`）尚未做运行时确认 —— **不影响字段表**，
   但做复刻时要注意"节点链"是挂在 `+0x18/+0x1C/+0x20` 三个槽上的，别和实体队列 `+0x28/+0x2C` 混。
