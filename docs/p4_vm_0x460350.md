## 1. `0x460350`：脚本流 VM 的单帧步进

### 1.1 签名与 `this` 布局

```
int __thiscall  0x460350(void)          ; this = 全局 0x56CC4C
```
* 帧：`0x460350 sub esp,0xCC` → `0x460356 push ebx` / `mov ebx,ecx` / `push ebp` / `push esi` / `push edi`（**无 SEH**）。
* **无栈参数**：三处收尾 `0x460401..0x460410`、`0x46069F..0x4606AB`、`0x4606C2..0x4606D1` 全是裸 `ret`。
* `0x460367` 的 `mov edi,[esp+0x10]`（= `S-0xCC`，未初始化局部）只在 op>0xE 的非法路径上被用到。
* 唯一调用者链：`0x451110`(页4 每帧) → `0x450FE0`(流程 VM) → `0x460350`；另有进场/切页采样点 `0x450D8D`、`0x450FE5`、`0x453136`、`0x453365`、`0x453D80`、`0x453ECD`。

对象 `0x56CC4C`（类 vtable `0x49988C`，ctor `0x460820`，dtor `0x460880`）：

| 偏移 | 类型 | 含义 | 写点 |
|---|---|---|---|
| `+0x00` | dword | vtable = `0x49988C` | `0x460820` |
| `+0x04` | dword | **当前帧计数**（本流的时钟） | 每帧 `0x46069C` `inc dword[+4]`；新流载入时 `0x460219` 清 0 |
| `+0x08` | word | **当前流资源 id**（45..76） | `0x4600F0`（`0x4600F4` 取 `word[+0xA]`） |
| `+0x0A` | word[16] | **待播 id 队列**（链的剩余部分，15 项 + 0 终结） | `0x4602D0` 装填、`0x4600F0` 左移出队 |
| `+0x2A` | word | **当前链索引**（= `0x4602D0` 的实参） | `0x4602D0`；读点 `0x460800` `return word[+0x2A]` |
| `+0x2C` | dword | 当前流脚本缓冲指针（malloc 得到；0 = 无流） | `0x46022C` 赋值、`0x460280` 释放清 0 |
| `+0x30` | dword | 记录游标（读指针） | `0x46022E` 复位到缓冲首、`0x4603EE` 前移 |
| `+0x34` | byte | 流终止/暂停标志（1 = 本链走完） | `0x460691` 置 1；`0x460280`、`0x460234` 清 0 |
| `+0x38` | 对象 | 标志子对象 = **`0x56CC84`**（BSS 清零起步，无 ctor 写点）；dword 旗标在 `0x56CC88`，即 **VM 冻结门**（`p4_stage_flow.md` §1.2 七位表） | 置/清全走旗标 API |
| `+0x3C` | dword | op0B 失败时 `0x4606BD` 置 bit0；亦被各冻结位共用 | `0x4606BD` `0x45AF30([this+0x38],1)` |

### 1.2 单帧算法（逐地址）

```
0x460350  sub esp,0xCC ; push ebx/ebp/esi/edi ; ebx = ecx = this
0x46035B  mov eax,[ebx+0x2C]
0x46035F  test eax,eax ; je 0x4606C2                 ; 无流 → return 1
0x46036B  mov al,[ebx+0x34] ; jne 0x4606C2           ; 已结束 → return 1
0x460376  push 0 ; lea ecx,[ebx+0x38] ; call 0x40145B ; = 0x45B030(0x56CC84, 0)
0x460382  jne 0x46069F                               ; 闸门 → return 0（VM 冻结）
```

`this+0x38` 就是旗标子对象，其地址 = **`0x56CC84`**（旗标 dword = `[0x56CC88]`）。
`0x45B030(obj,0)` 在 mask=0 时返回 **`flags != 0`** —— **七个冻结位（0x2/0x4/0x8/0x10/
0x20/0x40/0x80）任一置位，VM 时钟即停走**；置/清点全表见
[p4_stage_flow.md §1](p4_stage_flow.md)。op0B 失败时 `0x4606BD` 置的是它的 bit0。

```
0x460350  （续）
0x460388  LOOP:
            esi = [ebx+0x30]            ; 游标
            ecx = [ebx+0x04]            ; 帧计数
            ax  = word[esi+2]           ; 记录时间戳
            if ((int)eax > ecx)  goto 0x46069C   ; 未到点 → ++[ebx+4]，return 0
            op = word[esi]              ; 操作码
            if (op > 0xE) goto 0x4603EE ; 非法 op（edi 为未初始化局部）
            jmp [op*4 + 0x4606D4]       ; 0x4603A6
0x4603EE  ADVANCE:                      ; 唯一推进点（op0 除外）
            [ebx+0x30] = [ebx+0x30] + edi
            if ([ebx+0x2C] != 0) goto 0x46036B   ; 缓冲仍有效 → 继续取记录
            return 1                            ; 0x460404
0x46069C  ++[ebx+0x04] ; return 0
0x4606C2  return 1
0x4606AC  push 2 ; 0x45AF30(0x4AB5C0,2) ; push 1 ; 0x45AF30([ebx+0x38],1) ; return 1   ; op0B 载层失败（0x4606B3/0x4606BD）
```

要点：
* **时间戳比较是有符号 32 位**（`mov ax,[esi+2]` 后 `cmp eax,ecx` / `jg`），时间字段是 16 位无符号但按 0..0xFFFF 用。
* 一次调用会把**所有已到点的记录连续执行完**，只有"下一条未到点"时才 `++帧计数`；即每帧最多推进 1 帧时间。
* 返回值语义：**1 = 本流/本链已耗尽或未运行；0 = 正常运行中**（下一帧继续）。
* `edi` = 该 op 的**记录总长**（含 4 字节头）。op0 特例：`edi=0`，因为 `0x4600F0` 自己把游标指到新缓冲头部。

记录统一头：`+0` = op(word)、`+2` = 时间(word)；参数从 `+4` 起。
"推进量 edi" = 记录总字节数。

|---|---|---|---|
| **00** | 4（edi=0） | 无 | `0x4600F0(this)`：从 `word[+0xA]` 取下一 id → 装新流；失败则 `byte[+0x34]=1`（`0x460691`）。游标由 `0x4600F0` 重置，故不推进 |
| **01** | 0x14 (20) | `+4,+8,+0xC,+0x10` 四个 dword | `0x430400` 打包 20 字节 → `0x448FF0(ecx=0x4AD40C)` 入队（`0x460486`） |

| **03** | 0x14 (20) | 同上 | `0x43A3C0(ecx=0x4AD4CC)`（`0x460448`），实体 ctor `0x4355E0`（分配 0x48） |

### 2.1 五个入队原语 / 载荷打包（op01..05 共用）

`0x430400(dst, a, b, c, d)`（原始字节 `0x430400`..`0x430436`）：
```
sub esp,0x14
local[0] = arg2(a) ; local[1] = arg3(b) ; local[2] = arg4(c) ; local[3] = arg5(d)
edi = arg1(dst) ; rep movsd 5 → *dst = {a,b,c,d, STALE}
ret
```
⇒ **只写 4 个字**，第 5 个字是未初始化的栈残留（`0x430430` 之后 `rep movsd` 复制 5 个字）。消费端不要读 payload+0x10。

五个原语同形：`malloc`(`0x47C7C0`) → 实体 ctor 填字段 → 插入队列。
VM 传参顺序（以 op02 为例，`0x4603AD`）：`push &payload(@esp+0x18) ; push 0（第5参数，未用）; push d4 ; push d3 ; push d2 ; push d1` → `0x430400`；随后 `push &payload ; mov ecx,<队列> ; call <原语>`。

## 3. 脚本流 / 资源 / 装载（对应任务第 3 节）

### 3.1 资源访问（脚本与波形共用同一张表）

* `[0x5E14D8]` = 解包后的资源块基址（写入点 `0x45DC62`，读点 `0x45DD71/0x45DDAE/0x45DDF7`）。
* 表头是 **24 位、基址相对的紧凑偏移表**，id 从 **1** 开始：
  * `0x45DDA0(id)`（`0x4022E3`）：`ptr = base + u24(base + 3*(id-1))`
  * `0x45DDE0(id)`（`0x4011C7`）：`size = u24(base + 3*id) - u24(base + 3*(id-1))`
* 98 项（`resource_dec.bin` 头部 294 字节 = 98×3，与 `script_dump.py` 一致）；**id 45..76 = 32 个脚本**，id 1..20 = 20 首 MIDI，其余 = 图/波形/记录流。

### 3.2 op00 = "装下一条流" 的取值来源：`0x4600F0(this)`（`0x4014C4`）

```
0x4600F6  ax = word[this+0x0A]（队列头）；if (ax == 0) return 0        ; 0x46021C
0x460108  word[this+0x08] = ax                  ; 当前流 id
0x460111  把 +0x0A 起 15 个 word 整体左移一格（ecx=0xF 循环）
0x46011E  关卡号单调递增：表 @[esp+0x10..0x2C] = {0x2E,0x2F,0x30,0x31,0x32,0x33,0x34,0x3C}
              (46,47,48,49,50,51,52,60)  ← 即 Stg1..Stg7 与 LsBs
          for (k=1..8) {
            if (word[+0x08] == 表[k-1]) {
              if (0x45AFC0(0x4AB5B0, 0xF00000) < k)        ; 0x46017D
                  0x45B0E0(0x4AB5B0, 0xF00000, k)          ; 0x460191  (单调取大)
            }
          }
0x4601A2  if (word[+0x08] == 0x46(70)) 0x45AF30(0x4AB5B0, 0x80000000)   ; 置 bit31
0x4601BC  size = 0x45DDE0(word[+0x08])          ; 0x4011C7 → 0x45DDE0
0x4601C3  buf  = malloc(size)                   ; 0x47C7C0
0x4601CB  [this+0x2C] = buf ; if (buf == 0) return 0
0x4601D7  edi = size ; 0x4601E3 src = 0x45DDA0(word[+0x08])            ; 0x4022E3 → 0x45DDA0
0x4601F9  memcpy(buf, src, size)                ; rep movsd + rep movsb(余 0..3 字节)
0x460208  [this+0x30] = buf                     ; 游标回到缓冲首
0x46020B  byte[this+0x34] = 0
0x46020F  [this+0x04] = 0                       ; 帧计数清 0（新流自己的 0 帧）
0x460216  return 1
⇒ **op00 之后本帧继续执行新流的第 0 帧记录**（游标已指向新缓冲，循环继续），`edi=0` 不再叠加。

### 3.3 链装载 `0x4602D0(this, chain_index)`（`0x401D84`）

```
0x4602D0  0x460280(this)                     ; reset：帧计数/id/缓冲/暂停全清，free 旧缓冲
          word[this+0x2A] = arg               ; 链索引
          i = 0 ; 从 word[arg*2 + 0x499798] 起拷贝连续非 0 word（≤15 个）
                  word[this+0x0A + i*2] = w ; i++

* 调用点：`0x450D78`（页4 进场）、`0x45107F`（主链耗尽 → 9）、`0x4530AB`(0x5A)、`0x4530BE`(0x5C)、`0x4530D1`(0x62)、`0x453D6B`（实参由调用者算）。

## 4. `0x4CD590` 与 `0x4CD4A0`（命令 0 / 命令 9）

两者都是**每阶段在 `0x458D60` 里就地重建的对象**（该函数 `ret 0x10`，四个实参）：
`0x458DBA..0x458DC9` → `0x45EB40(0x4CD4A0, a0, a1)`；`0x458DCE..0x458DDD` → `0x460930(0x4CD590, a2, a3)`。
`0x458D60` 同时把 8 个实体队列（`0x4AD40C/43C/46C/49C/4CC/4FC/52C` + `0x4AD55C` 全停 `0x402324`→`0x457B90`）、序列引擎 `0x4CD484`、回放 `0x4CD5D8`、输入旗标一并重置。

### 4.1 `0x4CD4A0` = 本局成绩/记录对象（ctor `0x45EB40`，`ret 8`）

| 偏移 | 含义 / 依据 |
|---|---|
| `+0x04` | **当前分数**（结算累加处 `0x45F78A`、`0x45F7E4`） |
| `+0x08`,`+0x0C`,`+0x10` | 三个统计量（结算时两两取比值） |
| `+0x14..+0x20` | 计数量（`0x45EF10` 清零） |
| `+0x24` | word = **关卡号**（`0x45EF10` 写；`0x460E80` 读→`0x401889`） |
| `+0x2C` | word = ctor 实参 1（`movsx` 自字节，`0x45EB66/0x45EB7B`） |
| `+0x30` | dword = ctor 实参 2（`0x45EB95`） |
| `+0x34` | dword = `0xF4240`(1,000,000)（`0x45EB98`，分数上限/基准） |
| `+0x64` | 显示链表（`0x45A070` 构造） |

### 4.2 `0x4CD590` = 关卡进度对象（ctor `0x460930`，`ret 8`）

### 4.3 命令字（`this+0x2A` = 当前链索引）在流程 VM 里的语义（极性修正 2026-11-12）

流程 VM `0x450FE0`（无参数，裸 `ret`）。**注意 `0x45B030(obj,1)` = "位0是否全清"：

0x451020  0x45F760(0x4CD4A0)                     ; 链9 耗尽：离场结算
0x45102A  [0x4AB5C4] |= (0x45AFF0(0x56CCB8,0x40) ? 0x400000 : 0x200000)

## 5. 发射器（`0x4AD55C` 库 / 每帧 `0x457BD0` / 弹节点）

### 5.1 库结构

* 库对象 ctor `0x457AF0`：`0x463BCD(this+4, 0x2A98, 0xC, 0x401DED, 0x401E42)`（12 个通道，每通道 `0x2A98` 字节），vtable `0x499144`，`byte[this+0x1FF24]=0`。

* 全停 / 清库：`0x457B90`（`0x402324`，每阶段 `0x458D60` 调）→ 12×`0x457260` 后 `byte[0x4CD480]=1`。

### 5.3 每帧公式 `0x457380`（逐分支）

```
0x457380(ch):
  if (byte[ch+0x2A90] == 0) return                       ; 未激活
  if ([ch+0x2A88] != 0) {                                ; 连发中
      0x456D80(ch+0x30, ch+0x80)                         ; state += delta（20 字向量加）
      --[ch+0x2A88]
      0x456EB0(ch)                                       ; 用新 state 重建图案数组
  }
  ; 弹节点维护（0x4573C8..0x4573EB）
  node = [ch+4] ; prev = 0
  while (node) {
      if (0x457750(node)) { prev = node ; node = [node+0x30] }
      else { node = 0x457210(ch, node, prev) }           ; 摘链 + 虚析构 vtable[0](node,1)
  }
  ; 间隔判定
0x4573ED  ebx = [ch+0x68]                                ; 步进
0x4573F0  acc = [ch+0x2A94] + ebx                        ; 0x4573F6
0x4573F8  thr = [ch+0x64]
0x4573FB  [ch+0x2A94] = acc
0x457401  if (|acc| < thr) return                         ; 0x45740A jl 0x45743E
0x45740C  if (ebx >= 0) {                                ; 0x45740E jl 0x457426
0x457410      [ch+0x2A94] = acc - thr
0x45741D      0x457120(ch, acc - thr)
          } else {
0x457426      [ch+0x2A94] = thr + acc
0x457434      0x457120(ch, state[10] + (thr+acc) - 1)     ; [ch+0x58] = state[10]
          }
```
* `0x456D80(dst,src)` = 20 个 dword 逐字相加（`+0x00..+0x4C`，未展开为 rep）。
* `0x456EB0(ch)` = 依 `[ch+0x2A8C]` 旗标依次调用（`0x456EB3..0x456F08`）：
  `bit0→0x456F30`、`bit8→0x456FB0`、`bit4→0x456F70`、`bit12→0x457000`、`bit16→0x457050`（5/0x11111 全开）。
* `0x457120(ch, residue)`（`0x401EDD`）= **弹生成**：
  `node = malloc(0x34)`（`0x457139`）→ `0x457540(node, residue, ch+0xD0, ch+0x30, ch+0xC)`（`0x45715A..0x457170`）
  → 挂到链表尾：`if ([ch+4]==0) [ch+4]=node else [[ch+8]+0x30]=node ; [ch+8]=node`（`0x4571B8..0x4571C8`）。
  **没有全局队列**：弹节点属于该通道的私有链表。

### 5.4 op06 / op07 / op08 对通道的作用

* op06 → `0x4572E0(ch, ptr, flags)`（`ret 8`）：
  `[ch+0x2A8C]=flags`、`[ch+0x2A88]=0`、`byte[ch+0x2A90]=1`、
  `0x456D50(ch+0x30, ptr)`（20 字整块拷贝，`rep movsd 0x14`）、`0x456EB0(ch)` ⇒ **立即激活并按 state 建图案**。
* op07 → `0x457330(ch, ptr, flags, repeat)`（`ret 0xC`；VM 侧 `0x460574` 对 ch≥0xC 循环 12 通道广播，脚本以 ch=99 标注）：
  `if (byte[ch+0x2A90]) { [ch+0x2A8C]=flags ; [ch+0x2A88]=repeat ; 0x456D50(ch+0x80, ptr) }`
  ⇒ **只改 delta/旗标/连发数，不激活、不建图案**；通道未激活时整条记录是空操作。
* op08 → `0x457260(ch)`：20 字 state、20 字 delta、`0xA6E` 字图案数组、`+0x2A88/+0x2A8C/+0x2A90/+0x2A94` 全清 + `0x45A070(ch+0xC)`。

### 5.5 图案生成器（5 种，`count = state[10]`）

1. `0x456F30`（bit0）**整列对齐 X**：`d = (state[0]>>6) - pat[0].x ; for i<count: pat[i].x += d`
2. `0x456F70`（bit4）**整列对齐 Y**：同式作用于 `pat[].y`（`+0xD4`）与 `state[1]`
3. `0x456FB0`（bit8）**X 链**：`v=state[0]; a=state[3]; for i<count { pat[i].x = v>>6; a += (a*state[6])>>6; v += a }`
4. `0x457000`（bit12）**Y 链**：`v=state[1]; a=state[4]; for i<count { pat[i].y = v>>6; a += (a*state[7])>>6; v += a }`
5. `0x457050`（bit16）**kind 阶梯**：`u=state[2]`；阈值表 `[esp+8..]` = `{0,6,0xA,0x10,0x18,0x20,0x30,0x48,0x6C,0xA0,0xF0,0}`；
   `for i<count { while (u >= tbl[k]<<6) k++; pat[i].kind = tbl[k]; u += (state[5]*u)>>6 }`

### 5.6 弹节点（0x34 字节，vtable `0x499140`）

| 偏移 | 含义 |
|---|---|
| `+0x04` | 图案数组指针（`ch+0xD0`，**共享**） |

| `+0x10` | 外观档 0..3 |

| `+0x18` | 散布Y = `rand() % (state[9]+1)` |
| `+0x1C` | 上一帧的 kind（初值 -1） |
| `+0x20` | 当前 (kind × 散布X)>>6 |
| `+0x24` | 当前 (kind × 散布Y)>>6 |
| `+0x28` | 通道显示链表（`ch+0xC`） |
| `+0x2C` | 显示节点（`0x45A0E0` 分配） |

`0x457540(node, residue, pat, state, disp_list)`（`ret 0x10`）逐条：

[node+0x04] = pat ; [node+0x08] = state ; [node+0x0C] = residue

        r < state[15] → 0 ；< +16 → 1 ；< +17 → 2 ；否则 3   → [node+0x10]

`0x457750(node)` = 每帧一次（返回值 1 = 保留，0 = 销毁）：
```
0x457757  state = [node+8] ; residue = [node+0xC] + state[2] ; [node+0xC] = residue
0x457765  可见 = (state[11] <= residue <= state[12]) && (byte[state[19]] != 0)
              可见 → [disp+0x1C] = 1（0x45777D），否则 0（0x457786）
0x45778A  if (residue < 0 || residue >= state[10]) return 0        ; 生命周期结束

          if (kind == [node+0x1C]) goto 0x4578A5                    ; kind 未变 → 跳过重算
          [node+0x1C] = kind ; [node+0x20] = (kind*state[8])>>6 ; [node+0x24] = (kind*state[9])>>6
          if (kind <= 0xF0) [disp.d0] = 查表(0x457938/0x457908, kind) ;   ; 见下表
0x4578A5  e = pat[residue]
          if (e.kind == 0) { [disp+0x1C] = 0 ; return 1 }
          x = e.x + [node+0x20] - (kind>>1) ; y = e.y + [node+0x24] - (kind>>1)

**kind → 图形号**（`kind = pat[i].kind`，字节表 `0x457938` 241 项 + 跳表 `0x457908` 12 项；

| kind | 0 | 6 | 10 | 16 | 24 | 32 | 48 | 72 | 108 | 160 | 240 | 其它 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 处理 | `0x4577EC` | `0x4577F5` | `0x457800` | `0x45780B` | `0x457816` | `0x457821` | `0x45782C` | `0x457837` | `0x457842` | `0x45784D` | `0x457858` | `0x457861` |

⇒ 弹节点的"类型字"就是图案条目的第 3 个 dword（kind）：它①决定图形号 3..0xC，②按 `kind*state[8]>>6` 给出径向散布偏移，③以 `kind>>1` 做中心回退（形成逐渐扩散的环）。

## 6. op0C 的真实动作（`0x44F600`）

`0x44F600(this=0x4AB514, arg1, arg2)` `ret 8`；VM 传入 `arg1 = (param != 3)`、`arg2 = param`（`0x46064A..0x46065E`：

```

0x44F62B  0x44FDD0(this)                        ; 停当前曲

              return

0x44F6E2  0x44F0B0(this, tmp, src, len)          ; Huffman 解压（20 首 MIDI 均为压缩流）
0x44F6EE  byte[tmp+len] = 0
0x44F759  CoCreateInstance(CLSID @0x499C48, IID @0x4999E8, 3, 0, &obj)   ; call [0x5E7384]
0x44F7B1  obj->v[+0x4C](obj, 0x499A98, -1, 0, 0, [this+8])               ; 属性1
0x44F7C8  obj->v[+0x4C](obj, 0x499AF8, -1, 0, 0, [this+8])               ; 属性2

0x44F812  obj->v[+0x10](obj, ?, 0, 0, 0, ?, &tmp)  ; 起播
失败串：0x4A4780（v[+0xC] 失败）、0x4A4764（v[+0x10] 失败）
```
结论：op0C = **切换 BGM**（参数 = 资源 id 1..20 = 曲目号；`param==3` 时 arg1=0，走"不额外设置"的分支）。
**它不是阶段转换**：阶段切换由流程 VM 的页标志 + `0x4602D0` 链装载完成（§4.3）。

### 7.3 状态机（页4 → 流 → 页）（2026-11-12 订正）

链索引由页4进场参数块 `B+0x10` 决定（`0x4505B0` 三分支；**页13新游戏 `0x20000` → si=dword≥8、
bp=2 → 分支C → 链0 全周目主链**；页12选关 → 分支A/B 分关链），见
[p4_stage_flow.md §2](p4_stage_flow.md)。

```
[页4 进场 0x4505B0 → 0x450D6E: chain = word[B+0x10]]
        │  0x450D78: 0x4602D0(0x56CC4C, chain)   ; 装链 + 装第 1 条流
        │  0x450D7D: 0x45AF10(0x56CC84, 0)        ; 清冻结门
        │  0x450D8D: 0x460350                     ; 立即跑第 0 帧
        ▼
每帧 0x451110 → 0x450FE0 → 0x460350(this)
        │  返回 0（流内，或被 0x56CC84 冻结门挡住）→ 什么都不做
        │  返回 1（流耗尽）
        ▼
读 chain = word[0x56CC4C+0x2A]
  ├ chain==0  ─┬ [0x4CD590+0x40]!=0 → 0x45F760 结算 + [0x4AB5C4]|=0x200000（页8）
  │            └ ==0                → 0x4602D0(…,9)：进最终面（LsBs）
  ├ chain==9  → 0x45F760 结算 + |= (0x56CCB8 bit6 ? 0x400000(页9) : 0x200000(页8))
  ├ chain==0x2E → |= 0x400000（鍛錬）
  ├ chain==0x58 → |= 0x800000（鍛錬）
  └ 其它（11..39/0x2B/0x38..0x54）→ 无动作；离页靠 0x51000002(param=1) 的 0x10000
```
* 每次 op00 成功就换流：`+0x0A` 队列左移，`+0x04` 帧计数清 0 → **每条流都有独立的 0 帧基准**。
* 整条链的 id 队列耗尽（op00 返回 0）→ `byte[+0x34]=1` → 后续 `0x460350` 全部返回 1 → 触发上面的命令分支。
* **链内关卡切换靠 VM 冻结门**：boss 战（0x61000002 门，位0x2）、结算计数（0x51000001，位0x4）、
  二面 boss 控制器（0x64000001，位0x20）、庆典（0x66000002，位0x40）依次冻结/恢复时钟，
  使 op00 在恰当的时刻才触发。冻结位全表见 [p4_stage_flow.md §1](p4_stage_flow.md)。
