## 1. `0x4505B0` 阶段进场：参数块

完整清单 `docs/p4_listings/01_enter_4505B0.txt`（447 条）。要点：

- 块基址 `B = esp+0x10`，大小 **0xD4**（最后一条写入 `B+0xD2`）。
- `mov [esp+X], imm` 的块偏移 = `X - 0x10 - pend`（`pend` = 已压入未消费的实参个数）。
  本函数只有 `0x450651 push ebx` 造成 `pend=1`。
- `ebx` 在 `0x4505BA xor ebx,ebx` 之后**全程为 0**，故所有 `push ebx` / `mov …,bx|bl` 都是 0。
- 三条分支（`si = [0x4AB5C8]` 关、`bp = word[0x4AB5CA]` 周目）：

| 分支 | 条件 | 入口 | 内容 |
|---|---|---|---|
| A_flag | `0x45B030(0x4AB5B0,1)` 为真 | 0x450651 | 只写 5 个字段（`+0x10/0x12/0x14/0x16/+0x19=0x64`、`+0x1A=6`） |
| A | si<8 且 bp<=3 | 0x45069A | 两张 32 项表（`0x64`/`0xA4`）按 `si+bp*8` 取值 |
| B | si<8 且 bp>3 | 0x450943 | 常量 `si*4+0x38 / 0x320 / 0x64 / 0xC / 0xFF` |
| C | si>=8 | 0x45096E | 四张 4/8 项表（`0x3C`/`0x4C`/`0x54`/`0x5C`）按 `bp` 取值 |

**本轮修掉的真实 bug**：旧 `build_p4_block.py` 用 capstone 抽象求值，
遇到 `mov word [esp+0x3e], ax` 这类 16 位子寄存器就静默留 0 ⇒
分支 C 的四张表全成 0、`0x5C` 还串到别的区间（`0x190/0x320` 混进来）。

现改为 `remake/gen_p4_block.py`：直接解析反汇编清单，按上面两条规则提取，
输出 `remake/p4_block_tables.py`。生成结果与清单逐条可核：

```
0x3c [0,10,0,0,10,40,0,10]   0x4c [400,800,0,350]
0x54 [43,46,0,88]            0x5c [50,100,0,50]
0x64 [0,5,20,25,40,55,70,80,0,10,30,40,60,80,100,130,0,15,40,60,100,140,180,220,110,130,150,170,190,210,230,250]
0xa4 [0,20,50,80,110,140,180,220,15,40,90,120,180,250,350,450,30,70,180,250,430,570,760,950,1300,1400,1500,1600,1700,1800,1900,2000]
```

## 2. `0x451110` 里的进场循环

```
0x4514C3  mov al,[0x56CCB4]
0x4514C8  test al,al ; je 0x4514E2          ; 未置位 ⇒ 正常帧
0x4514CE  call 0x451630 ; test al,al ; je 0x4514E2
0x4514D7  loop: call 0x451630 ; test al,al ; jne loop
```

⇒ `[0x56CCB4]` 只是"**进入进场模式**"的一次性开关；一旦进入，
`0x451630` 会被**连续调用到返回 0**（每次调用都是一整帧：泵、present、输入、色带、渲染遍）。
`0x451630` 自己在首帧末尾 `0x4516A3` 把该字节清 0，但内层 `while` 只看返回值，所以进场不会中断。

## 4. 进场控制器实体 `0x423B30`（清单 `docs/p4_listings/04_intro_entity_423B30.txt`）

`t = [ent+0x1C]++`；`t-0x1E ∈ [0,0x96]` 时查表 `byte[0x423D84 + t-0x1E]`，
再 `jmp [0x423D6C + state*4]`。非 0 的状态只有 5 个：

| t | state | 地址 | 动作 |
|---|---|---|---|
| 30 | 0 | 0x423B5D | `0x460EC0(0x4CD590)` 非 0 且 `[ent+0x20]==0` ⇒ **`[0x56CCB4]=1`**（进入进场模式） |
| 35 | 1 | 0x423B89 | `0x460EA0(0x4CD590)` 非 0 且 `[ent+0x20]==0` ⇒ `0x45B010(0x56CC84,0x10)`，返回 0 |
| 50 | 2 | 0x423BBA | `0x430400(&rec, 0, 0x7F, 0x61000007, -8)` ⇒ `0x445AA0(0x4AD52C, rec)` 生成 0x61000007 |
| 120 | 3 | 0x423C01 | `0x44CDF0(1)` 恢复调色板；`byte[[ent+0x38]+0x1C]=1`（显示节点可见）；`0x448F50(0x4AD40C)`；`0x4301F0(0x4AD46C)` |

### 未解：开场实体被 `0x6B000001` 清空

现象（实测）：页4 f=0 时 op3 的 8 个实体已按 ctor 建好（位置与源矩形都对表），
但**同帧**全部消失。

原因链（地址已核）：舞台总控 `0x6B000001` 在 `0x454A6A` 由 `0x430400`+`0x43A3C0` 生成
（紧跟 `0x454A65 0x458D60` 场景重置），其 ctor `0x43D791` 把 `[+0x1C]` 清 0；
行为 `0x443606` 在 `[+0x1C]==0` 分支里调 **`0x43A320(0x4AD4CC)`**（= `0x43A4E0` 全部摘链
+ `0x430800` 释放节点），接着才生成自机 `0x4B000001`。

而流程 VM `0x460350` 在**同一帧更早**（`0x451327` 调 `0x450FE0`，早于 `0x4514B2` 的
`0x458E70` 派发）执行了 `t=0` 的 op3，把 8 个实体挂进 `0x4AD4CC`；随后派发序里
`0x4AD40C`（演员队列，总控在这里）先 tick、`0x4AD4CC` 后 tick ⇒ 被清掉。

实验：把 `0x43A320` 那次清空跳过，则 8 个实体存活并按行为移动（f=120 时
0x42000001 在 (144,742)、0x42000005 在 (346,510)），说明 ctor/行为/渲染链本身正确。

⇒ 剩余问题只有一个：**总控首次 tick 与脚本 t=0 记录的先后**。要么总控不在 f=0 tick
（其生成点或被 `0x460350` 的 `[+0x38]` 暂停位推迟），要么脚本 `t=0` 记录在 f=1 才执行
（`0x460350` 的 `[+4]` 帧计数起点）。查清这一点，开场动画就会自己出现，不需要改任何行为代码。
